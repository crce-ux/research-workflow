# AI 科研配图 — 路线选择与实测记录

> ### 一句话结论（2026-09-15 定稿）
>
> **自制示意图用玻尔 SciDraw 生成**（`bohrium.com/agent/scidraw`）；
> **需要矢量、或玻尔反复改不对时，改用我手绘的 SVG**（`_scripts/render_svg.py`，连接由像素级核验保证）。
>
> > ⚠️ **本文原先的结论是"关系类图必须手写 SVG，AI 抓不住拓扑"——已被玻尔实测推翻。**
> > 见 §二·六。原来的结论基于 5 个通用模型的全军覆没，但**玻尔做到了**。
>
> 依据：**十余次同题实测**（5 个通用模型 + sci-draw.com + 玻尔三种模式）+ 2 篇论文 + 4 个工具分析。

---

## 一、结论速查

| 图的类型 | 推荐做法 | 说明 |
|---|---|---|
| **机制图 / 环路图 / 通路图 / 流程图** | ✅ **玻尔 SciDraw 生成** | 形态质量最好；**但必须逐轮核验**（它会随机加东西）|
| 细胞形态、组织切片示意、概念氛围图 | ✅ 玻尔 SciDraw | 同上 |
| 封面图、图形摘要的视觉主体 | ✅ 玻尔 SciDraw | 同上 |
| **需要矢量 / 要投稿 / 要反复改版** | ✅ **手绘 SVG** | 连接由像素级核验保证，形态不如玻尔有机 |
| **玻尔反复改不对** | ✅ 手绘 SVG | 兜底方案 |
| 数值图表（柱状/箱线/森林图等） | matplotlib / seaborn | 与本文无关，见 `scipilot-figure-skill` |

**所以现在的判据是**：

> **① 要不要矢量（要投稿吗）？** 要 → SVG。
> **② 不要矢量 → 用玻尔，然后按 §二·六 的三查逐轮核验。**

**玻尔通常要改几轮才对。** 预算上按 **2–3 轮**估。

## 二、实测：五个模型画同一张图

**测试图**：屏状核局部抑制环路（PV 打胞体、SST 打远端树突、VIP 抑制 SST），含 5 个中文标注与 3 条抑制性 T 形端箭头。

**测试素材位置**：`屏状核_氯氮平/04_组会汇报/素材_示意图/`

| # | 模型 | 费用 | 中文文字 | 结构逻辑 | 判定 |
|---|---|---|---|---|---|
| 1 | `qwen/qwen-image(free)` | 免费 | ❌ 错字：树**籴** / 抑**臿** / 树**株** | ❌ 连线穿过胞体，T 形端全丢 | 不可用 |
| 2 | `kwai-kolors/kolors(free)` | 免费 | ❌ **全乱码**（込T / 籵T / 束适 / 彔黄） | ❌ **完全没理解任务**，全部元素画成六边形、凭空多出实体 | **最差** |
| 3 | `qwen/qwen-image-2.0-pro` | 付费 | ✅ 全对 | ❌ **PV 的线接到轴突上**（科学错误）、SST 穿过树突不停 | 不可用 |
| 4 | `bytedance/seedream-4.5` | 付费 | ✅ 全对 | ❌ 箭头全反向、两个标签悬空 | 不可用 |
| 5 | `google/gemini-3.1-flash-image-preview` | $0.067/张 | ✅ 全对 | ⚠️ 基本正确，**仅 SST 箭头悬空** | **最接近可用** |

**对应文件**：
```
AI生图_免费_qwen-image.png      （#1）
AI生图_免费_kolors.png          （#2）
AI生图_免费_qwen-pro.png        （#3）
AI生图_免费_seedream.png        （#4）
AI生图_屏状核局部环路.jpg        （#5）
测试_google_gemini-3.1-flash-image-preview_①②.jpg （对照：纯色块+文字，全对）
```

### 关键观察

1. **免费 ≠ 够用**。#1 #2 连"把字写对"都做不到。
2. **付费模型字对了，但连接逻辑错**。#3 把 PV 的抑制线接到了轴突上——这在神经科学上是**缺陷**，**比错字更危险**，因为看起来是对的。
3. **最好的模型也栽在同一处**。#5 唯一的问题就是箭头悬空——而"抑制打在哪里"正是这张图要说的事。
4. **对照组证明**：单纯画色块写文字时，#5 完全正确。**说明瓶颈不在文字渲染，在"拓扑关系的精确落位"。**

## 二·六、玻尔 SciDraw 实测（**这条推翻了前述结论**）

> **玻尔 SciDraw**（`bohrium.com/agent/scidraw`，深势科技）—— **与 sci-draw.com 是两个不同产品**，只是同名。
> 底层用 **ChatGPT Images 2.0**，主打"2 亿篇论文的配图惯例 + 1000+ 模板"。

### 三种模式的实测结果

| 模式 | 结果 |
|---|---|
| **Prompt → Figure**（纯文字） | ⭐ **最好**。细胞形态优秀、中文全对、**三条连接基本正确** |
| **Image → Image**（喂几何骨架草图） | ⚠️ 布局保住了，但**没把"圆"改造成细胞，而是"在圆旁边又加了一个细胞"** |
| **Image → Image**（再改一次） | ⚠️ 形态改对了，**但连接全乱**（VIP→SST 连接直接消失）|

**关键发现——一个反直觉的事实**：

> **在玻尔上，纯文字提示比喂几何骨架更准。**

我原以为"给骨架比给描述准"，实测相反。可能因为它（内部 prompt 机制）是为文本输入设计的。

**更深一层的发现——"把圆变成细胞"这个任务本身有矛盾**：

> **改形态 = 改边界；而所有连线落点都钉在旧边界上。**
> 模型要在"改造形状"的同时"保持端点不动"——**这两个要求在数学上对立**，
> 所以它只能任选一个牺牲：要么不变形态（保连接），要么变形态（连接随便落）。两次实测正好各占一边。

### 玻尔的脾性（实测，用前必读）

| | |
|---|---|
| ✅ 强项 | 神经元形态**明显优于手绘**；中文标注准确；**"删除 XX"类指令执行可靠** |
| ⚠️ 通病 | **每次生成/修改都会随机加东西**（多出的标签、字母、分叉突起）|
| ⚠️ 弱项 | **"把线延长到某处"常不执行**（试一次不动就别死磕）|
| ⚠️ 水印 | 底部有 `Bohrium AI Generated` 黑条，**用前裁掉** |
| 💡 提示词 | **写短**。它自带 rich-prompt rewriting，会自动扩写 |
| 💰 计费 | 每次生成/修改消耗积分。**按 2–3 轮预算** |

### 每轮必查三项

| 查什么 | 具体看 |
|---|---|
| **文字** | 中文标注**逐字**核对；有无错字、乱码、**混入英文** |
| **连接** | 每条线的末端（T 形端 / 箭头）是否**真的碰到**目标结构，而非停在半空 |
| **多余元素** | 有无**凭空多出**的形状、字母、标签、突起 |

## 三、学界证据

### 3.1 SciDraw-Bench（Chen 2026, arXiv:2606.28406）

为科研配图建立的专用基准，四个维度：文字保真度（TF）、语义正确性（SC）、结构质量（SQ）、学科规范符合度（CA）。

**论文列出的三种典型失败模式，与上表实测逐条对应**：

| 论文所述 | 本次实测对应 |
|---|---|
| Garbled Text（如把 PI3K 写成 PI3RK） | #2 Kolors 的「込T / 彔黄」 |
| Relation Inversion（抑制画成激活） | #4 Seedream 箭头全反 |
| Hallucination（凭空加实体） | #2 Kolors 多出的橙色圆球 |

**最重要的数据**：

> No system in the pilot study exceeded a **TF score of 0.74**.

**包括该论文自评的系统在内，没有任何模型的文字保真度超过 0.74。**

⚠️ **引用注意**：该论文同时评测了一个名为 SciDraw AI 的商业产品（自评 0.91，对比 Qwen-Image 0.64 / Ideogram v3 0.57）。**论文作者 Davie Chen 与 SciDraw AI 官网的负责人是同一人**——该分数属**厂商自评**，不可当作独立验证。

### 3.2 FigTree（Liu 2026, arXiv:2609.01006）

> 把科研配图生成建模为**递归的 SVG 程序构造**……**render-critic 精修回路同时检查渲染结果和底层程序，能把视觉缺陷追溯到具体语句并精确修复。**

**这是当前学界认为的正解：不让模型"画"图，而是让模型"写程序"，由渲染器出图。** 这样文字必然精确、坐标必然确定。

**我们手上的做法已经等价于这条路线**：`_scripts/render_svg.py`（渲染）+ 人工读图核对 = render-critic 回路，只是没有自动化。

## 四、工具可行性分析

**决定性判据**：能不能改 API 地址指向 CherryIN？（当前唯一可用的出图通道）

| 工具 | 能否改指 CherryIN | 前置条件 | 判定 |
|---|---|---|---|
| **FigureWeave** | ✅ **能**（源码级确认） | 需配置，非开箱即用 | 🥇 最值得试 |
| **NanaDraw** | ✅ **能**（配置项内置） | 环境已全满足，但安装重 | 🥈 次选 |
| **AutoFigure** | ❌ **不能**（在线托管） | — | 跳过 |

### 4.1 FigureWeave（开源 MIT）

`github.com/Krisocer/FigureWeave` — 从方法学文本生成可编辑 SVG。

**源码关键发现**（`src/figureweave/config.py`）：

```python
PROVIDER_CONFIGS = {
    'openrouter': {...},
    'bianxie':   {'base_url': 'https://api.bianxie.ai/v1', ...},   # 作者已内置中国中转
    'gemini':    {...},
    'openai':    {...},
    'anthropic': {...},
}
```

- `bianxie` 分支用 `OpenAI(base_url=..., api_key=...)` 调用，**返回格式解析的是 `![text](data:image/png;base64,...)` markdown** —— **与 CherryIN 返回格式一致**。改一行 `base_url` 即可指向 CherryIN。
- 流程：图像草稿 → 分割 → 资产提取 → SVG 重建 → 组装 → 迭代精修
- 支持多候选生成、图注条件化、双供应商路由

⚠️ **分割模型是门槛**：
- 默认 SAM3 —— 本机 **RTX 3050 Laptop 4 GB 显存大概率跑不动**
- 替代方案：`IDEA-Research/grounding-dino-base`（轻量，4 GB 可用）或云端 fal.ai / Roboflow（需另配 key）

### 4.2 NanaDraw

`github.com/Shannon4Science/NanaDraw` — 草稿 / 生成 / 组装三模式。

- ✅ 配置项明确支持 **`API Base URL`（自定义端点）** → 可指向 CherryIN
- ✅ 中文界面、250+ 参考图库、Bioicons SVG 素材、内置 draw.io 编辑器
- ✅ 本机环境全部满足（Python 3.13 / Node 24 / pnpm 11）
- ⚠️ 安装较重（前端 React + 后端 FastAPI + drawio 分支）

### 4.3 AutoFigure（跳过）

`autofigure.org` — 在线托管服务，5 积分/次。

- ❌ **无法改 API**：底层是它自己的流水线（Gemini 3.1 Flash 出草稿 + Gemini 3.1 Pro 做 SVG + SAM3 分割 + RMBG-2.0 去背景）
- ⚠️ **方法学文本需上传至其服务器**——未发表课题的内容出境风险

## 五、决策树

```
要画一张科研配图
│
├─ 是数值图表？ ────────────────→ matplotlib / seaborn
│
└─ 是示意图？
    │
    ├─ 需要矢量？（以后投稿 / 放大 / 反复改版）
    │   └─ 是 → ✅ 手绘 SVG + render_svg.py 渲染 + 像素级核验
    │
    └─ 否 → ✅ 玻尔 SciDraw 生成
              │
              ├─ 我出《自制示意图清单》（元素 / 连接 / 提示词 / 核验项）
              ├─ 你生成 → 发我 → 我三查（文字 / 连接 / 多余元素）
              ├─ 不通过 → 我给修改提示词 → 再生成   ← 按 2–3 轮预算
              └─ 通过 →（必要时 WPS 修图）→ 插入 PPT
                        │
                        └─ 若反复改不对 → 退回手绘 SVG
```

**⚠️ 两条不再成立的旧说法**（已被玻尔实测推翻）：
1. ~~"关系类图必须手写 SVG，AI 抓不住拓扑"~~ —— 玻尔做到了
2. ~~"喂几何骨架比给文字描述准"~~ —— 在玻尔上**恰好相反**

**⚠️ 仍然成立的一条**：**不要反复重跑同一提示词碰运气**。
玻尔的问题是**它会随机加东西**——所以正确的做法是**核验 → 针对性修改**，而不是重掷。

## 七、COI 与使用时注意

1. **SciDraw AI 的 0.91 是厂商自评**，引用时必须标注。
2. **数据出境**：CherryIN / OpenRouter / SciDraw 等均为第三方服务器。**未发表课题的机制假设不得写入 prompt**；纯教科书内容风险低。
3. **AI 配图必须人工核验**（SciDraw-Bench 原文结论），重点查：文字拼写、箭头方向与落点、有无凭空多出的实体。
