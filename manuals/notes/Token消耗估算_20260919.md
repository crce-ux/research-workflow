# 工作流 Token 消耗估算

> 2026-09-19。**依据本库真实产物体量反推**（屏状核_氯氮平、精神分裂症体重管理两个已跑通项目），非凭空估。
> **用途**：判断一次任务大概花多少、钱花在哪、哪里能省。

---

## 一、换算口径（先声明假设，否则数字没意义）

| 项 | 取值 | 说明 |
|---|---|---|
| 中文文本 | **≈ 1 token / 2.5–3 字节** | UTF-8 中文 3 字节/字；表格与 markdown 符号更费 |
| 幻灯片 PNG | **≈ 1.8k token / 张** | 1600×900，按长边 1568 缩放计 |
| **本库实测锚点** | 证据表 84.9 KB ≈ **24k token**；制作稿 67 KB ≈ **20k token** | 用于校准上表 |

> ⚠️ 以下全是**量级估算**，用于判断该花多少、钱在哪，**不用于精确对账**。

## 二、三档总量

| 档 | 典型规模 | 输入 | 输出 | **合计** |
|---|---|---|---|---|
| **轻** | 单篇分享，8–10 页 | 50–90k | 30–60k | **80–150k** |
| **中** | 组会汇报，16–20 页，24 篇 | 200–290k | 120–170k | **320–460k** |
| **重** | 系统综述 / 立项，>25 篇 | 450–700k | 250–500k | **700k–1.2M** |

## 三、中档逐阶段拆解（这是最常见的场景）

| 阶段 | 输入 | 输出 | 备注 |
|---|---|---|---|
| 规则装载（读总纲/手册/清单） | 10–30k | — | 只读本任务相关的 1–2 份即可 |
| 检索 + 元数据 + 摘要拉取 | 10–20k | 3–5k | 24 篇摘要 ≈ 10k |
| **证据表**（24 篇 × 12 列） | 15k | 12–18k | 实际 84.9 KB 那份是 44 篇 |
| 逐篇讲解 | 8k | 10k | 每篇 ~400 字 |
| 综述初稿（3600 字） | 6k | 4k | |
| 讲稿 / 内容稿 | 10k | 10k | 实测 33 KB |
| 内容自检 + 去味 | 15k | 8k | `check_language` 输出 + 逐项改 |
| **制作稿**（993 行） | 12k | 20k | **单次输出最大项之一** |
| 读版式依据（`ppt_style`/`ppt_kit`/配方库/骨架） | 20–35k | — | 每开新项目都要重读 |
| **SVG 逐页生成**（16 页） | 10k | **30–50k** | 实测单页 SVG 5.7 KB ≈ 2k；**含返工** |
| **视觉验证**（16 页 × 2 轮读图） | **45–60k** | 5k | **纯输入，且不可缓存** |
| 〔核查/审计〕（独立代理 + 对抗测试） | 40–70k | 15–25k | **可选**，见 §五 |
| **合计** | **200–290k** | **120–170k** | |

## 四、三个成本大头（**钱花在这三处**）

### 1. 读图验证 —— 45–60k，**纯输入且不可缓存**

16 页 × 2 轮（T2 导出后 + T3 定稿前）× 1.8k ≈ 58k。
**这是最"硬"的一块**：图必须逐张读，读一次算一次，没有复用办法。

> **可省**：T3 改成**重点页必看 + 随机抽 20%**（手册 §3.2 本就允许），页数多时立省一半。

### 2. SVG 逐页生成 —— 30–50k 输出

单页 2k 输出不算多，但**16 页 + 返工**就上去了。屏状核那次迭代到 v7，
SVG 反复重写是主要来源。

> **可省**：用 `PPT骨架模板_20260915/`（21 个整页骨架，复制即用）而不是从零写；
> 版式定了再动手，避免"边改内容边改版式"。

### 3. 制作稿 —— 20k 输出

993 行逐页七项素材，**写一次就够，但改一次等于重写**。
屏状核那份实战迭代到 v7，成本直接乘 3。

> **可省**：这就是「**制作稿先定稿**」这条铁律的**成本依据**——
> 不是流程洁癖，是每改一版多花 20k。

## 五、⚠️ 我新加的核查机制会增加成本

上一轮引入的机制不是免费的，**如实标注**：

| 机制 | 增量 | 什么时候值得 |
|---|---|---|
| 覆盖声明 | **≈ 0** | 永远值得——只是要求报数 |
| 独立代理复核 | +20–30k／轮 | 文本**要对外交付**时（审稿、投稿） |
| 对抗测试两段式 | +40–60k | 投稿前、或被质疑后 |
| `check_assets` / `check_metadata_leak` | ≈ 0（**脚本，不耗 token**） | 永远值得 |

> **原则**：**脚本能做的不要用模型做**。
> `check_language` / `check_consistency` / `check_assets` / `check_metadata_leak`
> 都是脚本，跑一次**几乎不耗 token**——这是你这套体系**已有**的最大成本优势。
> 新增的模型侧核查（独立代理、对抗测试）留给**真正高风险的文本**。

## 六、最大变量：返工

| 情形 | 倍数 |
|---|---|
| 一次过 | 1× |
| 迭代 v2–v7（屏状核实际） | **2–3×** |
| 跳到 B2/B3 顺序颠倒后重来 | **+50%**（去味工夫全废） |
| 跳证据表，后期人工抽补 | **+30–50%**，且**必然漏** |

> **返工是唯一能把中档推到重档成本的因素。**
> 「先建证据表」「内容未定稿不做 PPT」这两条铁律，**省的是 token 也是时间**。

---

## 七、省钱杠杆（按性价比排序）

| # | 做法 | 省 |
|---|---|---|
| 1 | **脚本做机械活**（`build_evtab` / `check_*` / `ppt_build`）| 每步数 k–数十 k |
| 2 | **A3 用弹药版而非完整版** | 手册称"最大的一块节省" |
| 3 | **T3 视觉验证改抽样**（重点页 + 20%） | 读图量减半 |
| 4 | **用骨架模板起页**，不从零写 SVG | 输出减 30%+ |
| 5 | **制作稿先定稿**，避免 v2–v7 | 最坏省 2/3 |
| 6 | 核查机制**只对高风险文本启用** | 中档可省 40–70k |

---

## 八、与人工工时对照

手册给的 AI 协作口径（24 篇模块）：**1–2 天**。
按上表 320–460k token，**大致相当于把两天的人工压成一次会话**——
真正省下来的不是 token，是**你在检索/抄数字/排版上的机械时间**。

> ⚠️ **但有个反向提醒**：token 便宜的部分（脚本、模板）已经用上了；
> **剩下的成本集中在"必须人判断"的地方**（制作稿、SVG、读图）——
> 这些恰恰是**不该省**的。省在这三处，返工时会加倍吐回来。
