## 一、⭐ 三条最关键的外部印证

### 1. 无头浏览器会被 CNKI 额外验证

**`ChengDSYJ-Studio/CNKI-Enhanced-MCP` 原文**：

> 「知网可能对无头浏览器触发额外安全验证，**因此当前搜索固定使用有头浏览器**。」

→ ✅ **与本项目实测完全一致**：我全程用 `--headless=new`，被拦；换有头后…… 仍被拦（但另有原因，见下）。

### 2. 验证码是**一次性**的，cookie 可持久

**`weileyao2005/cnki-deepsearch` 原文**：

> 「首次使用需完成 CNKI 验证码，**cookie 自动保存后续无需重复验证**。」

→ ⭐ **我的问题就出在没有持久化 cookie 上**：我每次都用**全新 profile**，等于每次都从"冷启动"开始，
**永远过不了首次验证**。正确做法是**固定 profile + 首次人工过一次**。

### 3. CNKI 检索走**内部 REST API**，不是 DOM

**`cnki-deepsearch` 逆向出的端点**：

```
restapi/citation-api/v1/literature/references          ← 参考文献
restapi/citation-api/v1/literature/citations           ← 引证文献
restapi/citation-api/v1/literature/quotations/metrics  ← 引用统计
openapi/usercenter-api/v1/recommend/similar/articles   ← 相似论文
restapi/citation-api/v1/literature/starter/domains     ← 关键词权重
```

**它的探索历程**（原文）：
> ① DOM 方案（失败）→ ② 全量抓包对比（转折）→ ③ **API 拦截方案（成功）**

→ ✅ **与我今天走的路径一字不差**：我也是 DOM 失败 → `listen` 抓包 → 抓到
**`POST /kns8s/brief/grid`**（主检索）+ `/kns8s/group/result`（分组）。

> **他们比我多走了一步**：把详情页的几组 citation/recommend API 也逆出来了。

## 三、⚠️ 三个必须由用户决定的问题

### 问题 1：CNKI 的验证码怎么过？

**三条路，各有代价**（**绕不过去，也不该绕**）：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 人工过一次**（推荐） | 固定 profile，**你手动拖一次滑块**，cookie 持久化 | 一次性，约 1 分钟 |
| **B. 打码平台** | `gleaner` 用**超级鹰 9602** 自动过 | **需付费积分**；且**第三方打码的合规性由使用者自担**（该项目自己声明"打码能力由你自行承担合规风险"） |
| **C. 机构权限** | 校园网 / VPN / 图书馆 WebVPN 登录 | 本项目**无机构账号**（见 FACT.md §〇）→ ❌ 大概率走不通 |

> ⚠️ **我不建议默认选 B**。它把"过验证"外包给第三方，合规责任转移到了使用者身上。
> **A 更简单，也更干净**——就是要你花一分钟手动过一次。

### 问题 2：要不要装第三方 MCP？

装 MCP 要改 Cherry Studio 配置。**Cherry Studio 是你的环境，该你定。**

### 问题 3：万方 / 维普怎么办？

现有工具**几乎都只做 CNKI**。而**万方/维普的拦截弱得多**——
本日实测：**维普用 URL 式检索直接出结果**（`qikan.cqvip.com/Qikan/Search/Index?key=U%3D<关键词>`）。

> 有 `GeoSchlor-MCP`（luskB）可能覆盖万方，**未细看**。

### 6.2 ⭐ 关键结论：维普的**布尔检索式不可用**（推翻先前判断）

本文件 §五 曾记「维普用 URL 式检索直接出结果」——**该结论只对单概念式成立**。
深入实测后发现**两种静默失效**（详见 `cnlit_search.py` 头部注释与 §五 实测记录）：

| 现象 | 表现 |
|---|---|
| 裸词无字段前缀 | 静默返回**无关的通用列表**，不报错 |
| 检索式含空格 | WAF **403** |
| 布尔式去空格后 | **解析错误 → 假阳性**：`M=(屏状核)AND M=(氯氮平)` 命中 3 条，**全部不含「屏状核」**（匹配的是字面「M胆碱受体」） |

> ⭐ **该假阳性在 UI 搜索框提交时同样复现** → 是维普自身的解析器问题，**不是 URL 编码问题**。
> **故本项目的正确用法 = 单概念式全量取回 → 本地筛查求交。**
> 工具已内置**硬拦截**：检出布尔运算符直接拒绝执行（需 `--force` 方可通过）。

### 6.3 由此得出一条可推广的纪律

> **「不报错」不等于「检索式生效」。**
> 任何检索式都必须配**对照组**（单概念命中数）来验证它确实被解析了。
> 「不报错」不等于「检索式生效」，与本项目已确立的「分层检索 + 对照组」纪律（FACT.md §五 Stage 1）**同源**。

### 6.5 ⭐⭐ 期刊质量过滤：用维普自带分级，**不要外挂期刊名单**

#### ① 先证伪了外挂方案（本次实测）

原计划吸收本文件 §二 提到的 **`gleaner` 的 `cnki_journal_tiers.json`**。实际下载验证后**弃用**：

| 文件 | 规模 | 实际学科 |
|---|---|---|
| `cnki_journal_tiers.json` | 340 种（tier1 18 / tier2 28 / tier3 294） | **经管 185 + 人文 134 + 理工 10，医学 0** |
| `intl_journal_tiers.json` | 96 种 | **经管 67**；其 `meta` 明写 `filter: Elsevier ∩ ASJC(14/20)`——ASJC 14=商业管理、20=经济金融，**学科定向筛选** |

**关键验证**：拿当轮 31 条记录的 **22 种中文期刊**去比对 —— **命中 0 / 22**。
（tier1/tier2 里全是《经济研究》《管理世界》《中国农村经济》一类。）

> 🔴 **教训**：**推荐一个工具前必须验证它的覆盖范围，不能只读 README。**
> 本次我是**先推荐、后验证**，验证才发现完全不适用。
> 「某项目有这个文件」≠「这个文件覆盖我们要的学科」。

#### ② 真正的解法：维普页面自带期刊级别

维普结果页左侧有一组**收录/级别筛选项，每项带计数**，且 `data-search` 属性给出代码：

```html
<a data-search="QK=bdhx#北大核心期刊" title="北大核心期刊">…<tt>14</tt></a>
```

| 代码 | 含义 | 代码 | 含义 |
|---|---|---|---|
| **`bdhx`** | **北大核心期刊** | `scopus` | Scopus |
| **`zgkjhx`** | **中国科技核心期刊** | `rccse` | 武大 RCCSE 核心期刊 |
| **`cscd`** | **中国科学引文数据库** | `pubmed` | 生物医学检索系统 |
| `jst` | 日本科技振兴机构 | `cas` | 化学文摘 |
| `ic` | 哥白尼索引 | `核心刊`/`普通刊` | 综合二分（仅在 facet JSON，无对应链接） |

**相比外挂名单的优势**：与记录**同源**、覆盖**维普收录的全部学科**、**不需要许可证**、**不会过期**。

⚠️ 与翻页同理：**筛选项只能点击，`&QK=bdhx` 无效**。

#### ③ 实例（屏状核）

31 条中：中国科技核心 18 · 北大核心 14 · CSCD 12 · Scopus 12 · PubMed 2。
**且这 14 篇北大核心期刊里，仍然一篇精神科都没有。**

> ⭐ **一般化**：**「数据源自带的元数据」通常优于「外挂的第三方名单」**——
> 前者与数据同源、同覆盖、同更新；后者要额外解决学科匹配、版本、许可证三个问题。

### 6.6 工具已支持

`_scripts/cnlit_search.py` 现默认打印级别分布，并支持：
```bash
cnlit_search.py vip "M=屏状核" --list-tiers        # 只看级别分布
cnlit_search.py vip "M=屏状核" --core              # 只留北大核心
cnlit_search.py vip "M=屏状核" --core zgkjhx       # 只留中国科技核心
```
