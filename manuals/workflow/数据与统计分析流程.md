# 数据与统计分析流程

> 建立 2026-09-19。**填补 D 段之后的第一个空白**——
> 《课题设计流程手册》定了 SAP，但**从"方案里写着要分析什么"到"结果真的算出来"这一段，此前没有流程**。
>
> **本手册管流程，不管统计方法本身。**
> 「该用哪个检验、样本量怎么算」属 **SAP** 与 **`nature-statistics` 技能**；
> 本文只回答：**什么时候做什么、要留下什么痕迹、和谁对齐**。
>
> ⚠️ **不提供临床或统计决策建议。** 涉及具体方法选择时，回到 SAP 与统计学家/导师。

---

## 〇、本流程的作用

**实测过的失分点**（本库与文献中的共同教训）：

> **预注册研究最常见的失分：方案里说好这么算，实际另算一套，且没记。**

```
D 段：写好 SAP（计划）
   ↓
❓ 执行时按什么算？偏离了怎么记？
   ↓
论文：审稿人问"与注册方案不一致"
```

**本流程的存在意义**：让**方案 → 数据 → 结果 → 论文**这条链**可追溯**。

## 二、五个环节

### 环节 1 · 变量字典（**采集前**）

**在收第一个数据点之前**定义清楚：

| 项 | 例 |
|---|---|
| 字段名 | `panss_total_bl` |
| 含义 | PANSS 总分，基线 |
| 类型 | 连续 / 分类 / 日期 |
| 取值域 | 30–210 |
| 缺失码 | `-9` 未评 / `-8` 不适用 |
| **来源** | 哪个表、哪次访视 |
| 对应假设 | D1 的哪一个子假设 |

> ⚠️ **"缺失码要区分"**——`未评`、`不适用`、`失访`、`拒答`
> **是四种不同的缺失**，合在一起会毁掉后面所有的缺失分析。

### 环节 2 · 数据采集与质控

**采集**：按 D3 的入排标准核对入组；按时点采集；**双人录入或系统校验**。

**质控（每次数据更新后跑）**：

- [ ] **范围检查**：超出取值域的值
- [ ] **逻辑检查**：入排矛盾、时序矛盾（访视日期早于基线）
- [ ] **重复检查**：同一受试同一时点重复记录
- [ ] **完整性**：计划时点 vs 实际采集时点，**列出缺失**
- [ ] **一致性**：同一变量在不同表中的取值是否一致

> 📌 **本库已有可复用件**：`check_consistency.py`（多源一致性）、`check_metadata_leak.py`（对外数据脱敏核查）

### 环节 3 · 缺失处理

**先描述，再处理。** 顺序不能反。

| 步 | 做什么 |
|---|---|
| ① **报缺失率** | 逐变量、逐时点——**报缺失率是必报项**，不是可选项 |
| ② **分缺失类型** | 未评 / 不适用 / 失访 / 拒答（见环节 1）|
| ③ **说明处理** | 按 **SAP 里写定的**方法（LOCF / MMRM / 多重插补…）|
| ④ **敏感性分析** | 按 SAP；**若 SAP 没写，就是偏离**（见环节 4）|

> 🔴 **不得事后挑选缺失处理方法**。SAP 写了什么就用什么；
> 想换 → 走环节 4 的偏离记录。

### 环节 4 · SAP 执行与偏离记录 ⭐ **本流程的核心**

**逐个假设**对照 SAP 执行，**每一条都留下痕迹**：

| 项 | 记录 |
|---|---|
| 假设编号 | D1 的 H1 / H2 … |
| SAP 原定方法 | 原文引用 |
| 实际执行方法 | |
| **是否一致** | ✅ / ⚠️ **偏离** |
| 若偏离 | **原因 + 何时决定 + 谁批准** |

> 🔴 **偏离要记录，偏离本身不算错误。**
> 论文里"与注册方案不一致"是审稿人必问项；
> **有记录 = 解释得清，无记录 = 说不清。**

**偏离的三种处置**：

| 情形 | 处置 |
|---|---|
| 数据不支持原定方法（如某组样本过少） | 记录 → 与导师/统计商定 → **在论文中说明** |
| 发现原定方法有误 | 记录 → **注册平台上更新并留痕** |
| 探索性分析 | **明确标为探索性**，不与确证性分析混报 |

### 环节 5 · 结果解读与报告

**产出**：结果报告（含表图与文字），供论文撰写使用。

**每条结果必须能回答**：

- [ ] 对应哪个**预注册假设**？还是探索性？
- [ ] **效应量 + 95%CI**（不只报 p）
- [ ] **分母**是什么（ITT / PP / 完成者）？**与 SAP 写的一致吗**？
- [ ] 缺失情况交代了吗？
- [ ] 多重比较校正了吗（按 SAP）？
- [ ] 有没有**事后选择**的痕迹（挑时点、挑亚组）？

> ⚠️ **与本库 `核查方法/02` 直接对接**：
> 该文档的七类失败模式（数字漂移 / 选择性呈现 / 聚合不匹配 / 差值错误…）
> **正是结果报告阶段的高发问题**。报告写完跑一遍。

## 三、数据形态的三点注意

> 依据：`SMART-CAT/数据清单与性别角度可研究问题_20260916.md` 与 TRS_EEG 项目实况

### ① 重复测量是常态（多时点）

数据多为 **基线 + 多点随访**（SMART-CAT 达 8 个时点）。
**注意**：

- 时点之间的**相关性**要在模型里交代（SAP 决定怎么处理）
- **不能用多个时点各跑一次 t 检验**代替重复测量分析
- 报告时**时点要标全**，不能只报"最后一个时点"或"最显著的一个"

> ⚠️ "挑最显著的时点报告"属 `核查方法/02` 的**选择性呈现**。

### ② 多中心数据

SMART-CAT 为 **7 中心**。注意：

- **中心效应**是否纳入（SAP 决定）
- **中心间实施差异**（评定者培训、量表版本）要能追溯
- 报告时**中心数要写**，不能只写总 N

### ③ 数据面调研的可信度分级

`SMART-CAT 数据清单` 用的 **🟢A级 / 🟡B级 / ⚪C级** 分级
（有论文佐证 / 仅注册库列明 / 摘要已报告）——**该分级做法应保留**：

> ⚠️ **"注册了" ≠ "采全了"。**
> 分析前须确认**哪些指标真正落地成了可分析的数据集**，逐项向数据持有方核实。

## 五、数据与统计自检清单

**采集前**
- [ ] SAP 在？（D 段有）
- [ ] 变量字典建了？
- [ ] 缺失码分了四类（未评/不适用/失访/拒答）？
- [ ] 预注册时点早于入组？

**采集后**
- [ ] 五项质控跑过（范围/逻辑/重复/完整性/一致性）？
- [ ] 缺失率逐变量报过？
- [ ] 缺失处理方法**与 SAP 一致**？

**分析时**
- [ ] 逐假设对照 SAP 执行？
- [ ] **偏离逐条记录了**（原因+时间+批准人）？
- [ ] 探索性分析**明确标出**？

**报告时**
- [ ] 每条结果能指到预注册假设？
- [ ] 效应量 + 95%CI 齐？
- [ ] 分母（ITT/PP）与 SAP 一致？
- [ ] 多重比较按 SAP 校正？
- [ ] 时点报全（未挑选）？
- [ ] 中心数写了？
- [ ] 跑过 `核查方法/02` 的七类失败模式？
