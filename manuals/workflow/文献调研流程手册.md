# 文献调研流程手册

> **本手册记录一套完整跑通、验证过的文献调研流程**——从证据表到 PPT 的四步管线 + 全程质量核查。
>
> **三次完整跑通的实证**：① 精神分裂症体重管理·模块B（24 篇）；② TRS_EEG·思路A（13 篇）；
> ③ 精神分裂症体重管理·候选课题 + 四模块核查。
>
> **通用性**：文中"模块X"泛指任何研究主题/子课题；模板、脚本、命令、踩坑清单**跨项目可复用**。

> ### 🔗 与总纲的编号对应
>
> 本手册按**内容**组织（检索 → 证据表 → 讲解 → 综述），用 `Step` 编号；
> 总纲按**阶段**组织，用 `A/B/C` 编号。**两者是同一件事的两种切法**：
>
> | 本手册 | 总纲阶段 |
> |---|---|
> | `Step 0` 检索与筛选 | **A1** |
> | `Step 1` 证据表 | **A2**（含 **G1 入库门禁**）|
> | `Step 2` 参考文献逐篇讲解 | **A3** |
> | `Step 3` 综述（叙事整合）| 总纲未单列——"综述"是 **B1 内容稿**的一种形态 |
> | `Step 4` PPT 稿 → PPT | 对应 **B4 → C1** |
> | §七 质量核查 | 分散在 **G1–G4** 四道闸门 |
>
> **凡遇"该做什么"看总纲，遇"怎么做"看本手册。**

## 一、流程总览（四步管线 + 质量贯穿）

```
                ┌───────────── 质量核查贯穿全程 ─────────────┐
                │ ① 元数据 ② 数据真实性 ③ 一致性 ④ 编号-引用双向 │
                └───────────────────────────────────────────┘

 检索筛选     → Step1 证据表     → Step2 逐篇讲解  → Step3 综述 → Step4 PPT稿 → PPT
 (PubMed/Google)  (xlsx+md)       (设计/数字/定位)  (四段式)    (内容稿+确认) (ppt-master)
     │                │                 │              │            │
     └─ 单一数据源 ────┴─────────────────┴──────────────┴────────────┘
          （xlsx 证据表为源，讲解/综述/PPT 数据与它完全一致）
```

**核心原则**

1. **单一数据源**：`证据表_模块X.xlsx` 是文献主数据源，讲解/综述/PPT 全部与它对齐（一篇不差、一个数字不改）。
2. **单向数据流**：证据表 → 讲解 → 综述 → PPT 素材 → 图表，避免返工。
3. **质量前置**：元数据（卷期页）在检索/导入时就用 Crossref 拿准，不事后返工。

## 一·五、各步完成条件 · 覆盖声明 · 预算

> ⚠️ 本节用 **§一·五** 编号而非插入新章，**为避免后续章节重编号**
> （本手册 §三–§九 被《出稿检查总表》A 侧、G0/G1 门禁等多处按章节号引用）。

### 各步「完成条件」

| 步 | 完成条件 | 怎么验 |
|---|---|---|
| **Step 0** 检索筛选 | ① 每篇有 PMID 或 DOI；② 分级（A/B/C）已定；③ 检索式与命中数**已留档** | 排他性断言须能指到分层检索记录（见 `术语表.md`）|
| **G0** 检索层质控 | 去重 / 存在性 / 元数据 / 版本**四项全过**；影响力仅**排序用，不淘汰** | `verify_pmid_doi` · `quality_screen` |
| **Step 1** 证据表 | ① 10 列 PICO 填全（期刊指标可后补）；② **PMID↔DOI 一一匹配**；③ 表内计数与检索命中数**可对账** | `verify_pmid_doi --pair` |
| **Step 2** 逐篇讲解 | ① 篇数与证据表一致；② 作者-年份集合对称；③ **每个数字回原文那一句核过** | `check_consistency` |
| **Step 3** 综述 | ① 正文 `[n]` 与文末编号表**一一对应**；② 支撑性引用**已判定语境**（非只核 DOI）| `check_ref_citations` · `核查方法/01` |
| **Step 4** PPT 稿 | ① 每个数字可追到证据表；② 每页七项素材齐备 | `check_consistency --auto-nums` |

> **本表管「流程内部出口」**；**「跑什么命令、判据是什么」见《出稿检查总表》§二**（管跨阶段门禁）。
> ⭐ **引用类口径见 `术语表.md`**——"已核实"只证明身份，**不证明内容支持**。

### ⭐ 覆盖声明（**强制**）

**凡是核查，都要能报出四个数**：

```
可识别位置总数 N  →  实际核查 M  →  **未能覆盖 K**（逐条列原因）
```

> 🔴 **只报"已检查"而不报"没检查什么"，等于假装覆盖完整。**
>
> | ❌ 不合格 | ✅ 合格 |
> |---|---|
> | 「引用已全部核实」 | 「28 处引用中核实 26 处；2 处因付费墙未读取，标未核实」 |
> | 「已逐篇核对数字」 | 「24 篇中核对 24 篇；其中 3 篇仅读到摘要，标证据深度=摘要」 |
> | 「代理已复查」 | 「代理覆盖 D1/D3/D7/D8/D17；D17 因源文件缺失未跑」 |

**四条细节**：① 正则／关键词搜索 ≠ 完整解析，无法解析的格式列为**覆盖缺口**；
② **未覆盖的部分仍算未核查**，不得默认通过；③ 读到的**深度要分级**（全文／摘要／前三页／仅标题），
不同深度**不能合并计数**；④ 计数须与记录对账。

### 预算与上限（未声明时按最保守执行）

| 项 | 默认 | 说明 |
|---|---|---|
| 检索轮数 | 2–3 轮 | 超了仍无结果 → 记"未检出"并停，**不无限重试** |
| 重试次数 | 3 次 | 限流(429)/超时；仍失败 → 记实际错误，**不隐瞒覆盖损失** |
| 独立代理轮数 | 2 轮 | 对接 `文本迭代自查流程` §七 止损（6 轮不收敛 → 停）|
| 联网 | **需明确授权** | 未授权时**只读本地已有材料** |

## 二、Step 0 · 检索与筛选（前置）

**多源并行**：PubMed 2–3 个简查询并行（复杂查询易超时，拆分）；Google 中英文补充（中文/预印本）；
用 NOT 排除不相关；限定年份 `"2020:2026"[Date - Publication]`。

**三级筛选**

| 等级 | 定义 | 处理 |
|---|---|---|
| A 类 | 原创/RCT/队列，主题直接匹配 | 精读 |
| B 类 | 原创但有差异 | 泛读 |
| C 类 | 综述/指南/方法学 | 扫读、找引文 |

**目标篇数**：每模块锁定 **15–25 篇**精读核心文献（B1–B4 分区，每区 4–8 篇）。

## 二·五、G0 · 检索层质控与质量快筛

> **为什么有这一道**：Step 0 此前是**纯操作、零检查点**——检出来的直接进证据表，
> 等 G1 才发现问题，**脏数据已经进表了。等于把过滤网装在下游。**
> 现前移至 **A1 之后、A2 之前**：四项不过，不进表。

### 第一部分：质控（四项，硬性）

| # | 项 | 怎么做 | 不过会怎样 |
|---|---|---|---|
| 1 | **去重** | 跨源合并，按 DOI/PMID 唯一化；无 DOI 用「标题+年份+一作」| 同一篇占两个坑、篇数虚高、一致性校验报错 |
| 2 | **存在性** | 逐条回源反查：`verify_pmid_doi.py --doi "…"`，或用 `quality_screen.py`（查不到会显式报出）| **引了一篇根本不存在的文献** |
| 3 | **元数据完整** | 标题/期刊/年/卷期页；缺的**显式标注**（如「中文期刊未注册 DOI」），**不留空** | 填表时才发现缺，返工 |
| 4 | **版本** | 标记 `[预印本]`/`[正式版]`；同一研究**只留一版** | 同一研究算两篇；或引预印本数据却标正式版年份 |

**通过标准：四项全过 → 才进 Step 1 建表。**

> ⚠️ **第 2 项对 AI 协作尤其要紧**：AI 给出的 PMID/DOI **可能编造**。
> **一律回源核，不得凭信**——包括那些"看起来很眼熟"的。

### 第二部分：质量快筛（排序，**不淘汰**）

```bash
python _scripts/quality_screen.py --pmid-file pmids.txt -o 快筛表
python _scripts/quality_screen.py --doi-file dois.txt -o 快筛表 --sort fwci
```

| 你要的 | 用什么指标 | 备注 |
|---|---|---|
| **高相关** | 标题 / 摘要 / concepts | **这是门槛，不是加分项** |
| **高被引** | `cited_by_count` + **`fwci`** + 被引百分位 / Top1% / Top10% | ⚠️ 必须用归一化指标，见铁律 2 |
| **权威作者/团队** | 通讯作者标志 + 机构 | 定位"谁在这个领域常驻" |
| **高 IF / 高分区** | 期刊 `2yr_mean_citedness`（近似 IF）+ h-index | ⚠️ 中科院/JCR 分区**需人工核对**，脚本不给 |

#### 🔴 四条铁律（**比指标本身更重要**）

1. **相关度是门槛，影响力是排序。** 不能因为 IF 高就留一篇不相干的——那是最常见的自欺。
2. **裸被引数不可用，必须按年份归一。** 实测：某 2026 年新文被引仅 **5 次**，
   但 **FWCI = 31.2、被引百分位 99.7%、Top 1%**。用裸被引会把最好的新文筛掉。
3. **影响力 ≠ 质量，且「权威的错误更危险」。** 权威团队也会犯错，
   而**权威的错误没人质疑**，因为大家默认它对。**标出来，但仍以证据本身为准。**
4. **外在不该覆盖内在。** 实测反例：本项目大量引用的 **Wong 2024 *Cells***（屏状核 5-HT 那篇），
   **FWCI 0.47、被引百分位 69.5%——低于本领域同龄平均水平**，但对本课题仍是关键证据。
   → **「对本项目关键」与「影响力高」是两件事，不要用一个否掉另一个。**

**产出**：`检索质控与质量快筛_<项目>.md`（+ `.csv`）

## 三、Step 1 · 证据表（数据地基）

**产出**：`证据表_模块X.xlsx`（主数据源）+ `证据表_模块X.md`（同内容，便于查看/git）

### 3.1 12 列模板（10 列 PICO + 2 列期刊指标，全项目统一）

| 列 | 说明 |
|---|---|
| 文献·DOI | 含 PMID/DOI（可溯源）|
| 作者·年份 | 第一作者+年，同年加 a/b |
| 研究设计 | 系统综述/网络荟萃/RCT/队列/指南/专家共识 |
| 人群 (P) | 诊断+样本量+关键基线 |
| 干预/暴露 (I/E) | 剂量/方式/时长，或非药物方案 |
| 对照 (C) | 无对照填 NA |
| 主要结局 (O) | 预设主要结局 |
| 关键结果 | 效应量+95%CI+p 值 |
| 局限 | 2–3 条 |
| 对本课题的意义 | 一句话：支撑哪个论点 |
| **期刊 IF** | **官方 JCR 影响因子**，须标年份，如 `4.4 (2024 JCR)`。⚠️ 用 OpenAlex 近似值须标注"近似" |
| **期刊分区** | **中科院分区（标版本）+ JCR 分区**并列，如 `中科院医学2区(升级版2025) / JCR Q2`。⚠️ 中科院分区有基础版/升级版差异、逐年变动，**不写口径等于没写** |

**分区组织**：按叙事结构分区（**B1 主题 → B2 → B3 → B4 → 总览框架**），
每区前加**藏青分区标题行**（合并单元格），区内部按证据等级高→低、同设计按年份倒序。

### 3.2 证据表相关脚本

**① 元数据批量核实** —— `pubmed_meta_fetch.py`
```bash
python pubmed_meta_fetch.py "12345678,23456789" -o 模块X_meta.json   # 或 --file pmids.txt
```
> 输出标题/期刊全称/日期/卷/期/页/前3作者/DOI；卷期页缺失（在线预发表/article number）
> 留空，由证据表标注"待出版方确认"，**不硬填**。

> **⚠️ 元数据来源优先级**：**PMID 已知时优先用 PubMed esummary**（一次性给全卷/期/页/DOI，
> 比"先查 DOI 再 Crossref"快且稳）；**无 PMID 时才走 Crossref 标题搜索**
> （`api.crossref.org/works?query.bibliographic=...`）定位 DOI。理由：① esummary 对
> article number（如 Biomedicines 14(7):1480）同样返回 pages 字段，Crossref 对部分不返回；
> ② 少一跳请求、少一次字段映射错位。Crossref 仅用于"有 DOI 无 PMID"或核对出版商卷期页。

**② 证据表生成** —— `build_evtab.py`
```bash
python build_evtab.py --data 模块X_evidence.json -o 输出目录 --module 模块X
```
> **数据 JSON 格式**：`[{"title": "分区1标题", "rows": [{authors, pmid, doi, design, pop,
> inter, ctrl, out, key, limit, meaning, journal_if, journal_rank}, ...]}, ...]`——与 12 列一一对应。
> `journal_if`/`journal_rank` 为**可选键**（中文期刊、预印本、新刊常查不到，留空即可）；
> 生成时脚本打印填写统计（如 `IF 12/13 · 分区 12/13`）。
>
> ⚠️ **坑**：分区匹配要**只按作者列**，勿把期刊名（如 "expert"）拼进匹配串，会误命中。

### 3.3 脚本沉淀规范（跨项目必读 ⭐）

**原则**：凡手写出可复用脚本/流程，**一律沉淀到 `scripts/`**，
勿留在单个项目临时目录。**详细规范（五步法 + 代码规范）见 `_scripts/README.md` §三**，本节不重复。

**⚠️ 脚本区维护约定**：

1. 脚本必须保持**数据驱动**（不硬编码某模块文献数据），模块数据放项目内 JSON
2. 新增踩坑/修复**同步回本区**（供所有项目受益）
3. 改脚本后跑一次 `--help` 或最小用例验证（`build_evtab` 额外用"缺字段/全字段"两个最小 JSON 回归）

## 四、Step 2 · 参考文献逐篇讲解

**产出**：`模块X_参考文献逐篇讲解.md`

**每条结构**

```
### N. 作者年份（短标题）— 期刊 卷(期):页 · PMID xxx
- **设计**：研究设计 + 样本量
- **人群**：诊断 + 关键特征
- **干预**：药物/方案（含剂量时长）
- **关键结果**：效应量 + 95%CI + p 值
- **模块定位**：这条证据支撑哪个论点
```

**关键点**：按叙事顺序（B1→B4→总览）编号，与综述引用条目一一对应；
**每个数字必须可溯源**；页码待确认的条目**明确标注**，不硬填。

**派生 · PPT 讲解稿**：从逐篇讲解提炼为 PPT 内容稿（每页 = 一句话结论 + 文献表 + 关键数字），
**交用户确认后才生成 PPT**（避免返工）。

## 五、Step 3 · 综述（叙事整合）

**产出**：`模块X_综述初稿.md`，目标 3000–4000 字。

**每节四步模板（防叙事割裂）**

```
【问题】 该维度要回答的核心临床问题？                        ~200 字
【证据】 按证据等级高→低呈现，每个关键结论紧跟作者-年份引用   ~2500 字
【局限】 证据短板                                            ~300 字
【建议】 可操作建议 + 衔接下一模块                            ~500 字
```

**结构范式（模块B）**：

```
B1 生活方式：基石但不足（STEPWISE 阴性）
B2 二甲双胍：首选辅助（疗效+预防+处方鸿沟）
B3 托吡酯及其他（托吡酯/恩格列净/益生菌）
B4 换用低代谢风险药物（换药权衡）
小结与衔接 → 引出下一模块（如 GLP-1）
```

**引用制**：作者-年份制（GB/T 7714 著者-出版年制）；效应量含单位与 95%CI；
正文标注证据等级（RCT/系统综述/网络荟萃/指南/专家共识）。

## 六、Step 4 · PPT 稿 → PPT

**产出**：① `模块X_PPT素材.md`（含 `[hero]`/`[primary]`/`[secondary]` 优先级标注）；
② `模块X_讲解.pptx`。

**设计**：每页 = **一句话结论 + 证据表（文献/设计/关键数字）+ 图表引用 + 衔接语**；
页面映射：封面 → 框架 → 各 B 分区（每区 1–2 页）→ 小结衔接。

**ppt-master 学术默认**

```
mode: pyramid（金字塔，结论先行）      visual_style: swiss-minimal
配色: 白底 + 藏青 #1F3A5F + 强调 #3A6EA5
字体: "Microsoft YaHei","Inter",sans-serif
page_rhythm: 封面 breathing / 内容页 dense
```

> ⚠️ **顺序（重要）**：**PPT 稿 → 用户确认 → 才生成 PPT**（避免返工）。

## 七、质量核查（交付前必做）

| 核查 | 方法 | 工具 |
|---|---|---|
| **① 元数据核实** | DOI→Crossref 解析，卷期页/页码对照 | `api.crossref.org/works/<DOI>` + PubMed efetch |
| **② 数据真实性** | 每个效应量/CI/p 值 vs 原文摘要 | PubMed 摘要 + Semantic Scholar 交叉验证 |
| **③ 一致性校验** | 证据表/讲解/综述/PPT 篇数与数字完全对齐 | `check_consistency.py` |
| **④ 编号-引用双向核查** | 正文 [n] 引用 ↔ 文末编号表一一对应（防缺失/悬挂/残留旧编号）| `check_ref_citations.py` |
| **⑤ 语言层自检** | 回指 / 排他性断言无出处 / 空泛量词 / **缩写未展开** / 数字口径 | `check_language.py` + `内容自检清单.md` |

**③ 一致性校验命令**

```bash
# 讲解模式（默认）
python check_consistency.py --evtab 证据表_模块X.md --explain 讲解.md --ppt PPT稿.md
# 综述模式（章节标题非"### N. 作者"格式，须加 --type review）
python check_consistency.py --evtab 证据表_模块X.md --explain 综述初稿.md --type review
# 关键数字全量自动覆盖（推荐，比抽查彻底）
python check_consistency.py --evtab 证据表_模块X.md --explain 讲解X.md --auto-nums
```

> 校验项：① 篇数一致；② 作者-年份集合对称（仅 explain）；③ 关键数字双源存在；
> ④ PPT PMID 对齐（自动兼容半角/全角括号）。**通过标准 = 四项全 ✅**。
> 思路A 实测：13 篇三处全对齐，23 项关键数字 auto-nums 全量通过（抓到并修正 1 处精度不一致）。

**④⑤ 的由来**：④ 源于整合综述曾被指出"正文引用但表内缺条目"——新增后正文引用与表内条目**零缺失零悬挂**；
⑤ 源于屏状核 × 氯氮平复盘——文稿里 ⓐ 跨段回指致引用不自足、ⓑ 排他性断言无出处、
ⓒ **缩写首次出现未展开**（`PV`/`VBM`/`ALE` 等）。前三项已脚本化，概念铺陈缺失见 `内容自检清单.md` §三。

**三类交付前审查**：PPT 真实性（逐页数据 vs 摘要）· 证据表内容核查（逐条效应量 vs 摘要）·
逐篇讲解审核（定向核实存疑数字）。每类产出**独立报告落盘**。

## 九、踩坑清单（复用前必看）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | pyzotero 方法名 `add_to_collection` 不存在 | 用 **`addto_collection`**，第二参传**完整 item dict** |
| 2 | 卷期页码用推断值 → 事后返工 | **检索/导入时就用 Crossref 拿准**，引用核查前置 |
| 3 | matplotlib 中文变方框 | `font.sans-serif` 首位必须 **"Microsoft YaHei"** |
| 4 | Crossref 对 article number（e70/BMC 编号）不返回页码 | 标"待出版方确认"，不硬填 |
| 5 | `create_items` 返回布尔非列表 | 计数用 `get_collection_items` 验证实际入库数 |
| 6 | xlsx 被 Excel 占用无法写入 | 生成"分区版/优化版"新文件 → 用户关闭后替换 |
| 7 | 分区脚本期刊名误命中（"expert"含"per"）| 只按"作者·年份"列匹配 |
| 8 | 正文引用但证据表缺篇 | 以"综述参考文献条数"为准，倒查证据表补齐 |
| 9 | Windows Python 中文路径/输出乱码 | `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` |
| 10 | PPT 稿 PMID 用全角括号（如`（26955358）`）| 一致性脚本已兼容半角/全角；勿用只匹配 `(PMID xx)` 的正则，会误报"0 个 PMID" |
| 11 | 证据表关键数字非摘要原文（如 Meta g 值）| 数值保留但**在"局限"列标注来源**，防事后无据可查 |
| 12 | 效应量方向符号（d 负值=应答者某指标更低）| 用方向中性描述（如"应答者 D 发生减少，d≈-1.01"），或标注取绝对值 |

## 十·二、存量资产反向合规（已有产出物时）

**适用场景**：历史项目已有 PPT、讲解、综述，但**没建过证据表**
（如 TRS_EEG 思路 A 曾"PPT 先行、证据表后补"）。此时**不可跳过证据表直接进入下游**，
需先反向补地基、再正向校验：

```
已有 PPT/讲解/综述
    │ ① 反推：从各文档提取 作者-年份 + PMID 全集，合并成文献清单
    │       （以 PMID 为准，剔除重复；"有文无 PMID"的要追补）
    ▼
② 补证据表：build_evtab.py --data 生成 xlsx+md（12 列逐条填写）
    │       （关键结果列必须回到 PubMed 摘要核对，勿从旧 PPT 抄）
    ▼
③ 反向校验：check_consistency.py（篇数/作者集合/关键数字/PMID 全对齐才算合规）
    ▼
④ 同步修正：发现不一致 → 以 PMID/摘要为准修正证据表 → 重跑校验
```

**关键规则**

- **PMID 是唯一去重锚点**（旧文档标题可能不准确）
- 反向补的证据表**不得从旧 PPT 抄关键结果**——一律回 PubMed 摘要核对
- 完成反向合规后，后续改动一律走正向"先改证据表再同步下游"

> **思路A 实证**：PPT 先行 → 反推 13 篇 → 补证据表（esummary 核卷期页 + 摘要核数字）→ 三处全对齐。
> 发现并修正 1 处（Rieger g 值来源标注）、2 处卷期页提示。
