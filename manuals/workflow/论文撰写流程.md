## 二、六个环节

### ① 定贡献（**不可跳**）

> **`paper-spine` 的核心设计就是"贡献优先、先确认贡献再逐单元设计"。**

**写作前先回答**：

- 这篇论文**主张什么**？（一句话）
- 它比现有文献**新在哪**？
- **证据够不够支撑这个主张**？

> ⚠️ **贡献定不了就别动笔**——这是本库 `课题设计流程手册` D1
> "证伪条件"的同一逻辑：**说不清要证明什么，就写不出可检验的论文**。

### ② 搭骨架

**IMRaD 结构**（大多数原创研究）：

```
Introduction  →  为什么做（问题 + 缺口）
Methods       →  怎么做（可复现）
Results       →  发现了什么（只报不说）
Discussion    →  意味着什么（含局限）
```

**骨架阶段要定的**：

- [ ] 主图 / 主表是哪几个（**先定图表，再写文字**）
- [ ] 每个结果对应哪个假设
- [ ] 局限有哪些（**主动列**，不等审稿人问）

### ③ 分节撰写

用 **`paper-spine`**（12 阶段编排，中文投稿命中率导向，输出 LaTeX/PDF/Word）；
需要 Nature 风格分节时用 **`nature-writing`**（摘要/引言/方法/讨论分节撰写）。

> 📌 **顺序建议**：Methods → Results → Introduction → Discussion。
> **Methods 和 Results 最客观，先写不易被带偏。**

### ④ 语言润色

用 **`nature-polishing`**（Nature-leaning English + LaTeX 排版修复）。

> ⚠️ **润色不得改动事实**——数字、单位、分母、方向词（增/减、优/劣）。
> 本库纪律：**润色改动若违反保真红线，一律回退**。

### ⑤ 本文核查 ⭐ **本库特有，技能不含**

**这一环是本文存在的核心理由**——把已有核查机制接到论文上：

| 核查 | 用哪件 | 查什么 |
|---|---|---|
| **引用身份与语境** | `核查方法/01` | 每处引用是否真实存在、是否**支持你写的那句话** |
| **数字与范围** | `核查方法/02` | 七类失败模式（数字漂移/选择性呈现/聚合不匹配…）|
| **承压测试** | `核查方法/03` | 先写敌意拒稿 memo，再请零上下文裁决者判"当前文本是否已回应" |
| **引文自足** | `check_language.py` | 回指、排他性断言、缩写展开 |
| **编号-引用** | `check_ref_citations.py` | 正文 `[n]` ↔ 文末表 |
| **多版本一致** | `check_consistency.py` | 中英/正文/图表数字一致 |
| **身份泄露** | `check_metadata_leak.py --scene blind` | 盲审场景下的文档属性 |

> 🔴 **顺序**：**01 → 02 → 03**。
> 先确认引用是真的（01），再确认数字是对的（02），最后才做承压（03）——
> 前两步没过就做压力测试，是在测一个地基不稳的房子。

### ⑥ 投稿前自审

用 **`academic-paper-reviewer`**（5 人模拟：EIC + 3 审稿人 + Devil's Advocate）。

**再叠加本库两道**：

- **`核查方法/03` 两段式**——它比 5 人模拟多一样东西：**判断"当前文本是否已回应"，而非"是否已修复"**
- **`check_metadata_leak.py --scene blind`**——盲审身份泄露（**硬门槛**）

### ⑦ 选刊投稿

→ `SCI投稿_选刊流程.md`（`journal_match.py` 硬过滤 + 软判断四问）

## 三、与国自然板块的分工

两个板块都涉及"写作"，但**性质不同**：

| | **论文撰写**（本文）| **国自然标书**（`国自然标书_诊断与架构手册.md`）|
|---|---|---|
| 产出 | **实证结果**的呈现 | **研究计划**的论证 |
| 起点 | 已有数据 | 尚未做的研究 |
| 核心 | 结果 → 主张 | 缺口 → 假设 → 方案 |
| **AI 边界** | 可大幅辅助（写作/润色/核查）| 🔴 **不得直接生成申请书** |
| 表达层 | `nature-polishing` | `标书去机器味_四层扫描法` |

> ⚠️ **别混**：论文可以 AI 协助写；**标书不行**。
> 这是 NSFC 明文规定，不是风格偏好。

## 四、投稿前自检清单

**内容层**
- [ ] 贡献一句话说得清？
- [ ] 每个结果对应一个假设？
- [ ] **局限主动列了**？
- [ ] 分母（ITT/PP）交代了？
- [ ] 缺失情况报告了？

**核查层**（顺序不可颠倒）
- [ ] `核查方法/01` 引用身份 + 语境判定过？
- [ ] `核查方法/02` 七类失败模式跑过？
- [ ] `核查方法/03` 两段式承压过？
- [ ] `check_language.py` 排他性断言 = 0？
- [ ] `check_ref_citations.py` 编号零缺失零悬挂？
- [ ] `check_consistency.py` 多版本数字一致？

**交付层**
- [ ] `check_metadata_leak.py --scene blind` 跑过？（**盲审硬门槛**）
- [ ] 目标期刊格式要求核对过？（→ `SCI投稿_选刊流程.md` 软判断四问）
- [ ] 与预注册方案的一致性说明写了吗？（→ `数据与统计分析流程.md` 偏离记录）

> ⚠️ **最后一条最容易被忽略**：若 SAP 有过偏离，
> **论文里要主动说明**——审稿人一定会问，主动说比被问出来好。
