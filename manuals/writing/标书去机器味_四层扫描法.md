## 〇、本文管什么

| | |
|---|---|
| **管** | 标书**正文的表达层**——去掉机器味，恢复研究主体与动作 |
| **不管** | **不新增信息、事实、方法、指标、结论、落点或格式** |

> 🔴 **一条规则**：**只改表达，不改事实。**
> 组织层面的"边界声明过重""研究动作不清"可以改写法，**但不能补写内容**。

---

## 一、四层扫描框架

从外到内四层，**逐层扫，不要跳层**：

### 第 1 层 · 词语

| 模式 | 处置 | 例 |
|---|---|---|
| 套话 | 删 | 随着社会的发展 · 越来越受到广泛关注 |
| 抽象标签 | 还原为**原文已有的动作** | 具有重要理论意义 · 是本研究的关键抓手 |
| 连接词堆砌 | 拆 | 首先/其次/最后、因此/从而/进而 连环 |
| 元评论 | 删或合并 | 值得注意的是 · 需要指出的是 |
| 临时造词 | 改写；**对象不确定则人工确认** | 四态终结 · 有界使用政策原型 |

### 第 2 层 · 句法

| 模式 | 处置 |
|---|---|
| **伪对立**（「不是 A 而是 B」「不只是 A 更是 B」） | **真边界**：保留并弱化模板感<br>**伪对立**：把 B 放入主干<br>**同义递进**：合并，**不补事实** |
| 无主语流程句 | 补回**原文已有的**主体，不新增职责 |
| 嵌套括号 / 长分号串 | 拆成句流 |
| 八步以上箭头 | 按职责拆分 |
| **规格书句法**（同句堆动作/配置/版本/失败/验收） | 先保会影响复现的字段，再按职责拆；**字段若含阈值/权限/分母/失败处理，不得删** |

### 第 3 层 · 段落

| 模式 | 说明 |
|---|---|
| **工程协议腔** | 入口/出口 · 状态映射 · 队列 · 载荷 · 闸门 · 终态 · 整包 · 静默补写 · 失败码<br>连续出现时**恢复研究主体和动作**；确属实现细节则保留并**首次中文释义** |
| 中英项目语域混杂 | 改为「**中文总括 + 必要英文括注**」 |
| **边界压过动作** | 通篇讲约束，却看不出**做了什么研究** |
| 口号 / 模型自我辩护 | 删除或合并 |
| **连续动词无主语** | 「归入、映射、锁定、冻结、收缩、降级」连用却无研究人员/评分者/数据管理员作主语 → **补回原文已有主体** |

### 第 4 层 · 章节 ⭐（**最容易漏，也最重要**）

**建立「事实 — 首次完整定义 — 后续引用」表**，按章节职责区分：
目标 / 内容 / 方法 / 质控 / 年度计划。

**规则**：冻结、污染、样本、边界规则**只在一个章节完整说明**，
其他章节保留本节必需的短句；**疑似有意重复则人工确认**。

> ⚠️ **本层的动作顺序是「先归位，再润色」**——
> 若段落本身放错了章节，逐行润色是白费工夫。

## 二、⭐ `section_roles`：章节职责表（**本法的核心**）

**本表是全法最容易被漏掉、也最关键的一张表**——
它决定"第 4 层章节扫描"的判据：**这段话该不该待在这一章**。

| 章节 | 职责 |
|---|---|
| **立项依据** | **问题驱动，明确研究缺口** |
| **研究内容** | 说明**研究动作、边界、步骤和验证口径** |
| **研究基础** | 按**证据链**写清已有结果与局限 |
| **工作条件** | 将**资源逐项对位到研究任务** |
| **风险应对** | 说明**风险、触发条件、影响和备选方案** |
| 通用 | 只按原文职责判断，**不强行套用其他章节结构** |
| 其他 | 先确认章节职责，再决定保留或合并内容 |

### 用法

**逐个段落问：这一段在写什么？它该待在这一章吗？**

> **实测案例**：一份标注为「立项依据」的文本，四段里有**三段**在写技术流程、
> 设计参数、统计假设——**全是「研究内容」的职责**。
> 而真正该写的"研究缺口"只有一句。
>
> **处置**：不是在**写技术流程、设计参数、统计假设的这三段**上逐行润色，而是**先判定归属**——
> 属于研究内容的段落**建议移走**，而不是就地删改。

> ⚠️ **归属决定属结构性改动**，超出"只改表达"的范围——
> **须人工确认，不得擅自搬移**。

## 三、术语三分法

**专业术语不自动判为机器味**——英文或代码出现不构成删除理由。

| 类型 | 处置 | 例 |
|---|---|---|
| **受控术语** | **逐字保留** | `\texttt{RELEASE}` · `H_0` · 统计量 · 模型名 · 接口字段 |
| **可保留术语** | 首次中文释义，后文用**稳定短称** | `manifest` · `fail closed` · 参考包络 |
| **临时造词** | **优先改写**；对象不确定则**人工确认** | 四态终结 · 纯暴露解释 |

## 四、安全不变量与 token 保护

### 4.1 逐字保护清单（**改写时不得触碰**）

```
LaTeX 命令 / 环境 / 参数        \cite{} \ref{} \eqref{} \item
引用 key · label · 数学 · 公式
数字 · 单位 · 变量 · 缩写 · 专名 · 编号
路径 · URL · 邮箱 · DOI
特殊字符 / 转义 · 注释 % 后内容
换行 / 空行 / 缩进 / 列表结构
状态 / 接口 token：\texttt{RELEASE} · \texttt{ABSTAIN} · H_0 · H+A · A-only
```

### 4.2 安全不变量表（**只提取原文实际出现的**）

```
状态 / 权限 · 阈值 · 分母 · 暂停与失败处理 · 探索性定位 · 规划资源边界
```

**改写后做「原句 — 改写句 — 不变量」对照。**

> 🔴 **无法证明零损失 → 保留原句，并标「人工确认」。**

### 4.3 输出前复核 token diff

逐项列出 protected token，比对改写前后——
**无脚本时手工列清单**。**复核 token diff 这一项不可省。**

## 五、执行流程（七步）

```
1  读取参数和章节职责；未给章节按「通用」，不推断新事实
2  标记受保护片段，建立术语表和安全不变量表
3  按四层扫描；每项给出 保留 / 改写 / 合并 / 人工确认 + 理由 + 不可改变的含义
4  真实二分保留边界并弱化模板感；伪对立把 B 放入主干；同义递进合并
5  先做章节去重 / 职责归位，再逐行润色；抽象标签还原为原文已有动作
6  自评：
      第 1 轮 —— 看自然度、主体、章节职责
      第 2 轮 —— 看不变量、LaTeX / 数学 / 数字 / 代码 token、结构
      只跑 1 轮时，同时记录两类结论
7  复核 token diff、术语稳定性、不变量；按输出模式交付
```

**每项处置只能四选一**：`保留` / `改写` / `合并` / `人工确认`。
**不允许"顺手改改"** ——每一项都要有理由。

## 六、参数与输出模式

| 参数 | 取值 | 说明 |
|---|---|---|
| `section_type` | 通用 / 立项依据 / 研究内容 / 研究基础 / 工作条件 / 风险应对 / 其他 | 决定第 4 层判据 |
| `field` | general / cs / engineering / **medicine** / life_science | **只调已有术语的语域，不增事实** |
| `strength` | minimal / moderate / **aggressive** | 改写力度 |
| `output_mode` | text_only / **text_with_change_summary** / diagnosis_only / text_with_change_summary_and_style_card | |
| `self_eval_rounds` | 1 或 2 | 见第 6 步 |

## 七、回归样例（用于自检）

### 样例 A · 研究内容

**输入**：研究人员先核对病例状态，再依据 `manifest` 中的模型、环境、提示模板、证据、权限和输入输出版本执行评分；若状态不是 `\texttt{RELEASE}`，则归入 `ABSTAIN`，不赋予临床方案分数。随后按"入口校验→状态映射→队列冻结→失败码记录→出口审计→终态发布"完成整包处理，并以 `H_0`、`H+A`、`A-only` 分层记录结果。

| 诊断 | 处置 | 必须保留 |
|---|---|---|
| `manifest` 字段串 | 保留并中文总括，首次释义 | 版本、权限、输入输出、失败处理 |
| 箭头流程 / 工程协议腔 | 拆为研究动作；实现细节可保留 | 顺序、冻结、审计 |
| 受控 token | 逐字保留 | `\texttt{RELEASE}`·`ABSTAIN`·`H_0`·`H+A`·`A-only` |
| 无主语风险 | 保留"研究人员先核对"这一**已有**主体 | **主体不改写成新职责** |

### 样例 B · 风险应对

**输入**：若拒答率接近全拒答，则暂停扩展，不将低条件风险解释为成功；规划样本量只用于方案设计，不能写成已落实资源。值得注意的是，本方案不是追求漂亮结果，而是保持沉默并不争夺主要结论。

| 诊断 | 处置 | 必须保留 |
|---|---|---|
| 拒答阈值 / 暂停 / 解释边界 | 保留或仅做句法润色 | **不能把"接近全拒答"冒充成功** |
| 规划与资源边界 | 保留 | **规划 ≠ 已落实** |
| 元评论与伪对立 / 口号 | 直接写研究判定或合并 | **不新增风险处置或结论** |

### 通过条件

1. 每项输出 `保留/改写/合并/人工确认` 之一并说明理由
2. LaTeX、数学、数字、代码状态、分层 token **无 diff**
3. 阈值、分母、暂停条件和资源边界**可逐项追溯**
4. **不删除全部工程术语，也不强行补写方法**

## 四层扫描的判据
- **词语**：套话 / 连接词堆砌 / 抽象标签 / 元评论 / 临时造词
- **句法**：伪对立 / 无主语流程句 / 嵌套括号 / 长分号 / 八步以上箭头 / 规格书句法
- **段落**：工程协议腔 / 中英语域混杂 / 边界压过动作 / 口号或自我辩护
- **章节**：对照下表判断段落是否待在正确章节

| 章节 | 职责 |
|---|---|
| 立项依据 | 问题驱动，明确研究缺口 |
| 研究内容 | 说明研究动作、边界、步骤和验证口径 |
| 研究基础 | 按证据链写清已有结果与局限 |
| 工作条件 | 将资源逐项对位到研究任务 |
| 风险应对 | 说明风险、触发条件、影响和备选方案 |
| 通用 | 只按原文职责判断，不强行套用其他章节结构 |

## 约束
🔴 逐字保护：LaTeX 命令/环境/参数、引用 key/label、数学、数字/单位、变量/缩写/专名/编号、
   路径/URL/DOI、特殊字符/转义、注释 % 后内容、换行/空行/缩进/列表结构。
   状态 token（\texttt{RELEASE}、\texttt{ABSTAIN}、H_0、H+A、A-only）逐字保护，只可在自然语言中释义。
