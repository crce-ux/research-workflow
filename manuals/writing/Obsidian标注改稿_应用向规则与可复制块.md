# Obsidian 标注改稿 · 应用向规则与可复制块

> 方向：**人标注 → agent 执行修改 → 清标记 → 留变更记录**。
> 与 `Obsidian标注回写_插件与skill调研.md` 配套（那份管选型，这份管执行）。
> 语法基础：CriticMarkup。**本文件是规则，不是技能包**——要改稿时把 §七 的可复制块粘到会话开头。

---

## 一、触发与前提

**什么时候用**：作者在 Obsidian 库的 .md 里用 CriticMarkup 标好了要改的地方，说"按标注改"。

**前提检查（动手前先做）**：
1. 文件在 `D:\Obsidian\2026\5\` 库内（本会话工作目录即库根，**Read/Edit/Write 直达，不需要 MCP**）
2. 文件里确实存在标记。**先扫一遍再动手**——用这个正则数命中数：

   ```
   \{\+\+|\{--|\{~~|\{==|\{>>|\{=\+|\{[a-z]+="
   ```

   与肉眼看到的条数对账（★ 本项目既有教训：「解析出的条数必须与标称命中数对账」，
   对不上就是漏了，且不会报错）

   ⚠️ **末尾那支 `\{[a-z]+="` 不是凑数——它是必需件。**
   标记带前缀时（`{author="Chen"--删--}`），标记符**不紧贴 `{`**，前六支**一个都匹配不到**。
   **实测**：只写前六支，8 行样本（六种标记各带前缀 + 两种无前缀）**只命中 2 行，
   六种带前缀形式全军覆没**；补上 `\{[a-z]+="` 后 **8/8**，且在干净文本上**零误报**
   （`2019--2022`、`a >> b`、`{x + 1}` 均不误报）。
   这一漏最要命的地方在于：**前缀正是区分「本人标的」与「上一轮 agent 标的」的唯一依据**
   （见 §三之五）——漏掉带前缀的，等于把 §三之五 的判据整个架空。
3. 判定标记的作者归属（见 §三之五）

---

## 二、标记语义（解析表）

| 标记 | 含义 | 应用向的动作 |
|---|---|---|
| `{++新文字++}` | 建议增加 | 在原位插入「新文字」 |
| `{--旧文字--}` | 建议删除 | 删除「旧文字」 |
| `{~~原~>改后~~}` | 建议替换 | 用「改后」替换「原」 |
| `{==某段==}` | 高亮，**只说"看这里"，不说怎么改** | **不单独执行**——就近找配对的 `{>>…<<}` 取意图 |
| `{>>批注<<}` | 批注 / 意见 | 按 §三之三 分类处理 |
| `{=+已插入文字+=}` | 由 AI/协作者**已经写进正文**的文字 | 视为正文，**只剥外壳、保留文字** |

### 前缀（可选）

```
{author="Chen" date="2026-10-12"~~原~>改后~~}
```

- 位置：`{` 之后、标记符之前
- 规则：键**小写**、值**双引号**、`{` 后**无空格**、最后一对引号**紧贴标记符**、值内**不得含 `"` `{` `}` 或换行**
- **解析时前缀要吃掉**，别把 `author="Chen"` 当成正文内容

### 配对规则（决定批注指向谁）

- `{==某段==}{>>为什么<<}`——**紧邻无间隔**时，批注针对该段
- `{~~原~>改后~~}{>>理由<<}`——**紧邻**时，批注是这条建议的理由
- 中间**只要隔了正文或换行**，两者**各自独立**，不要强行绑定

## 三、执行规则

### 一、总原则：**标注是命令，不是提示**

看到了就办。不要把标注当成"供参考的意见"再自己判断一遍要不要改——
但也不要把标注当成"可以随意发挥"的许可（见 §四 三条边界）。

### 二、按顺序处理

1. **先扫全文**，建一份标注清单（位置 / 类型 / 内容 / 作者）
2. **分类**（§三之三）
3. **能定的直接改，不能定的留标记**
4. **改完剥壳**（§三之四）
5. **出变更记录**（§六）

### 三、批注的分类（这是最容易出错的一环）

`{>>…<<}` 的内容分三类，**处理方式完全不同**：

| 类型 | 例子 | 处理 |
|---|---|---|
| **明确改法** | 「改成 2023」「这句删掉」「把结论提前」 | **执行** |
| **任务 / 待核** | 「这个数字要核对」「查一下这个引用对不对」 | **不改正文**，列入「待办」 |
| **疑问 / 讨论** | 「这句会不会太满？」「这里要不要提局限？」 | **不改**，列入「待确认」并给出你的判断 |

> 判据：**批注里有没有一个可直接落地的改法。** 有→执行；没有→列出来，别替作者做决定。

### 四、剥壳规则

改完后，**正文里不得残留任何标记外壳**——`{++`、`{--`、`{~~`、`{==`、`{>>`、`{=+`
一个都不许剩（含前缀）。

**唯二例外**（保留原样，不动）：
- §三之三 中判定为「待核 / 待确认」的批注——**保留标记**，让作者回头看
- 含义不明、无法安全执行的标注——**保留标记**

> 剥壳后**自查一遍**：用 §一 的**完整正则**重新数一次——**别省掉末尾那支 `\{[a-z]+="`**，
> 命中的应该**只剩**上述两类例外。
> 这是「不报错 ≠ 生效」的直接应用——**改完了不代表改干净了，要数一遍。**

### 五、作者归属

- `author="Chen"`（或用户本人的署名）→ **本轮的指令源，执行**
- `author="Claude"` / `"GPT"` 等 → **上一轮 agent 留下的**，**不要当成作者的指令**
  ——警惕循环：agent 自己标、自己改、自己再标
- 无前缀 → 默认视为作者本人
- **归属存疑** → 列入待确认，不执行

### 六、不做的事

- **不解析代码块内的标记**（``` 围栏内一律当普通字符）
- **不处理嵌套 / 重叠 / 跨段落的标记** → 列入待确认
- **不顺手润色没被标注的地方**。标注范围之外的一个字都不改。

---

## 四、三条边界（硬约束）

1. **含义不明 → 不猜。** 保留标记，列入「待人工确认」。
2. **标注要求与证据冲突 → 不执行。** 例如要求删掉真实存在的局限、要求把观察性关联写成因果、
   要求补一个查不到的引用——**提请复核，说明为什么不该改**。
   （对齐 Agent 系统提示词：不生成未经验证的研究数据）
3. **批量删除 / 合并条目 / 整节推倒 → 先确认。** 
   单点改动（一句话的增删换）直接办；**删掉一整段以上，或涉及文件结构重组，先给清单。**
   有意的删除**必须留一行说明**。

> 补充：**改前没有 git 兜底**（库不在版本控制下）。所以 §六 的变更记录**不是可选件，是唯一凭证。**

## 五、执行示例

**改前**
```markdown
本研究纳入了 48 例患者{++（其中首发 12 例）++}。
样本量较小{~~因此结论需谨慎~>，结论限于本队列的观察范围~~}。
{==总体应答率 55.1%==}{>>这个数字要与 SMART-CAT 原文再核一遍<<}
{>>摘要前五句里问题和贡献都出来了吗？<<}
```

**改后**
```markdown
本研究纳入了 48 例患者（其中首发 12 例）。
样本量较小，结论限于本队列的观察范围。
总体应答率 55.1%{>>这个数字要与 SMART-CAT 原文再核一遍<<}
{>>摘要前五句里问题和贡献都出来了吗？<<}
```

**变更记录**
| # | 原文 | 改后 | 依据 |
|---|---|---|---|
| 1 | 48 例患者 | 48 例患者（其中首发 12 例） | `{++…++}` 插入 |
| 2 | 因此结论需谨慎 | ，结论限于本队列的观察范围 | `{~~a~>b~~}` 替换 |
| 3 | ——（残留标记） | 保留未执行 | `{>>…<<}` 属「待核」，非改法 |
| 4 | ——（残留标记） | 保留未执行 | `{>>…<<}` 属「疑问」，需作者定 |

## 六、产出格式

**两件，缺一不可：**

1. **改后的干净文件**（原地覆盖，标记已剥净）
2. **变更记录**——同目录 `<文件名>_变更记录_YYYYMMDD.md`，含三张表：
   - **已执行**：编号 / 原文 / 改后 / 依据哪条标注
   - **保留未执行**：编号 / 标注原文 / 为什么没改（待核 / 待确认 / 归属存疑）
   - **本次更正了什么**（若有多轮迭代则必备——对齐用户「报告多版迭代时要保留『本次更正了什么』小节」）

聊天框只给**摘要 + 路径**，变更明细落盘。

## 七、可复制块

> 要改稿时，把下面整段粘到会话开头（或直接说「按 `Obsidian标注改稿_应用向规则与可复制块.md` 干」）。

```
我已在 Obsidian 库的 markdown 文件里用 CriticMarkup 标好了要改的地方。请你按标注执行修改。

【语义】
{++x++} 增加；{--x--} 删除；{~~a~>b~~} 用 b 替换 a；{==x==} 只是高亮、须就近找配对的
{>>…<<} 取意图；{=+x+=} 是已写入的正文，只剥壳保留文字。
前缀形如 {author="Chen" date="2026-10-12"~~a~>b~~}，解析时吃掉，别当正文。
{==x==}{>>…<<} 紧邻无间隔才配对；中间隔了正文或换行就各自独立。

【执行】
1. 先 grep 数一遍标记命中数，正则用 \{\+\+|\{--|\{~~|\{==|\{>>|\{=\+|\{[a-z]+="
   （最后一支 \{[a-z]+=" 专门捞带前缀的标记，不能省），
   与肉眼条数对账，对不上先报告、别硬改；
2. 建标注清单（位置/类型/内容/作者）；
3. 分三类处理 {>>…<<}：明确改法→执行；任务待核→不动正文、列入待办；
   疑问讨论→不动、列入待确认并给出你的判断；
4. 作者 author 是 C 开头（本人）才当指令；author 是模型名的是上一轮 agent 留下的，不执行；
5. 改完剥净所有标记外壳，再 grep 复核一遍，命中的应只剩保留项；
6. 代码块内的标记不解析；嵌套/重叠/跨段的列待确认。

【边界】
- 含义不明不猜，保留标记列入待确认；
- 标注要求与证据冲突（如删掉真实局限、把关联写成因果、补查不到的引用）→ 不执行并说明理由；
- 删整段以上或重组结构 → 先给我清单确认；有意的删除留一行说明；
- 标注范围之外一个字都不改，不顺手润色。

【产出】
改后的干净文件（原地覆盖）+ 同目录《<文件名>_变更记录_YYYYMMDD.md》，
含「已执行 / 保留未执行 / 本次更正了什么」三张表。聊天框只给摘要和路径。

现在，文件是：<路径>
```

## 八、与既有资产的关系

| 资产 | 分工 |
|---|---|
| `Obsidian标注回写_插件与skill调研.md` | **选型**：装哪个插件、为什么排除另两个 |
| **本文件** | **执行**：agent 拿到标注后怎么干 |
| `写作禁用词与句式清单.md` + `check_language.py` | 改完之后的**语言门禁**——本流程只管执行标注，不替代它 |
| `文本迭代自查流程.md` D23 | **身份层**（像不像作者写的），与标注执行是两个维度 |
| `工作日志模板.md` | 变更记录 ≠ 工作日志：前者逐条记改动，后者记里程碑 |

> ⚠️ 待验证：本规则**尚未在真实标注上跑过**。首次使用后，把实际暴露的问题补进 §九。
