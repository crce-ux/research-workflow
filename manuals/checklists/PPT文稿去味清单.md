# PPT 文稿去味清单

> **建立**：2026-09-12 ｜ **配套**：`汇报PPT产出流程手册.md`（§二 流程 ①.5 / ②.5）
> **工具**：`humanizer-zh-academic` skill（已安装）｜ 内置规则源自 `nature-paper2ppt/references/design-and-layout.md`
> **性质**：可直接照着做的操作清单。做 PPT 时在 ①.5 和 ②.5 两个节点各过一遍。

---

## 〇、先读这条：PPT 不是论文

`humanizer-zh-academic` 是**为论文段落**设计的，直接套到 PPT 上会大面积误报。两者载体不同：

| | 论文 | PPT 制作稿 |
|---|---|---|
| 载体 | 连续段落 | 要点条目 + 讲稿备注 |
| 并列结构 | 是 AI 味（等长等重的三段论） | **是要点列表本身，是排版要求** |
| 加粗 | 是修饰，≤5 处 | **是视觉层次手段，必须有** |
| 论证顺序 | 现象先行、理论后置 | **结论先行**（标题就是结论） |
| 最佳实践 | 打破节奏、注入学者个性 | **页面文字要克制，个性留给讲稿** |

**实测数据**：把 skill 的规则跑在 `组会汇报_PPT制作稿_20260912.md`（822 行）上——20 个内容层触发词命中 **0**，但加粗 **369 处**（skill 硬约束是"全文 ≤5 处"，差 74 倍）。所以第 1 节的三条豁免是**必须设置的**，否则 skill 会把 PPT 的加粗全部剥掉。

---

## 一、PPT 专用豁免与修正（用 skill 前先设这三条）

| skill 原规则 | PPT 场景处理 |
|---|---|
| 正文加粗 ≤5 处 | ❌ **豁免**。改用**覆盖率**标准，不用个数标准（个数标准已被实测证伪，见下）。 |
| 整齐三元并列 每段 ≤1 处 | ⚠️ **半豁免**。要点列表的并列**保留**；但查两点：① 三行是否**等长等重**（等长就打破，让重要的一行长）；② 是否是"理论/实践/方法"这类**凑数三连**（是就删到两条）。 |
| 「依据/基于 XX 理论」起笔 ≤20% | ❌ **不适用**。PPT 页面文字本来就结论先行，不写文献综述式起笔。此条只在**讲稿备注**里查。 |
| 注入学者个性（第一人称、表达意外、承认局限） | ⚠️ **分层**：讲稿备注 ✅ 全用；页面文字 ❌ 完全不用。 |

### 加粗标准：用覆盖率，不用个数（2026-09-12 实测修正）

初版写的是"每页 ≤3 处"，跑真实制作稿后被证伪：S6、S12 各 9 处加粗，看着超标，翻开一看全是 **降低 / 抑制 / 增高 / 不作为论据** 这类方向词和判断词——正是该加粗的。反过来，一页只有 1 行文字却加粗 5 处，才是滥用。

**正确标准按覆盖率判**：

| 判据 | 通过 |
|---|---|
| 加粗落在**数字、效应量、方向词、关键判断词**上 | ✅ |
| 加粗行数占页面文字行数的比例 **< 60%** | ✅ |
| 整段整句被加粗（而非个别词） | ❌ 改为只加粗核心词 |
| 加粗铺满全部要点（等于没有层次） | ❌ 削减到只留最关键的两三处 |

## 二、禁用短语（扫一遍，除非引用原文）

```
一句话总结        最有价值的后续方向      不是……而是……
不只是……更是……    值得注意的是           总的来说
从某种意义上      提供了新的视角          具有重要意义
未来可以进一步探索  奠定了基础             深入探讨
至关重要          此外（句首连续使用）    综上所述 / 由此可见
专家认为（无出处）  研究表明（无出处）
```

**`不是……而是……` 的例外**：承担"排除竞争解释"的论证功能时**保留**（如"不是药物本身，而是疗效的不可预测"）；只是修辞上的"先立后破"节奏，删掉。

> 实测：全科研库扫 13 个高危短语，命中 9 个为 0；`不是…而是…` 44 次抽样看基本都是论证性用法。**这条要人工判，不要机械删。**

## 三、五个高危句式（科研 PPT 重灾区）

| 句式 | 症状 | 改法 |
|---|---|---|
| **空泛评价** | "具有重要临床意义""为该领域提供了新思路" | 换成具体：效应量多少、样本量多少、改变了哪个决策 |
| **万能句式** | 一句话能套到任何论文上 | 点名本文的方法/数据集/机制/图表证据/局限 |
| **凑数三连** | "快速、准确、可靠" | 用含义需要的数量，不凑三 |
| **总结腔** | 每节末尾加一句升华 | 删掉，让最后一个具体事实结尾 |
| **模糊归因** | "研究表明""专家认为"无出处 | 点名：作者年份 + `[n]` 角标 + PMID |

**万能句式的判据**（来自 nature-paper2ppt）：

> 如果一句话能套到任何一篇论文上，就重写它，直到它点名了本文的方法、数据集、机制、图表证据或局限。
>
> Weak：一句话总结：该方法具有重要意义。
> Better：该方法把检索、证据补全和答案生成拆成可审计流程，降低了遗漏关键文献的风险。

## 四、分场景力度（对应制作稿七项）

| 制作稿项 | 力度 | 可用 skill 的哪些规则 |
|---|---|---|
| ① PPT 标题 | `in-place` | 仅换词。标题是信息密度最高的位置，宁短勿修饰 |
| ③ 页面文字 | `in-place` | **只用"换词 + 去模糊归因 + 删填充短语"**；禁用"破对称""注视角" |
| ④ 表格数据 | **不动** | 表格只查口径，不做文风处理 |
| ⑤ 图注 | `in-place` | 换词；必须写清口径（哪个人群、哪个指标、什么单位） |
| ⑥ 讲稿备注 | `bounded` | **全规则可用**——这是 skill 最适用的地方，口语化 + 注入研究者判断 |
| ⑦ 口径提醒 | **不动** | 防失真内容，禁止改写 |

### 讲稿备注专用：口语化的三个动作

实战返工的首要原因就是"讲稿备注写成书面语"（手册 §八）。三个动作：

1. **加一句研究者判断**："我的判断是……""我倾向认为……"
2. **承认不确定性**："这里数据不够理想""如果老师问到，我不想让它看起来像我漏了"
3. **拆长句**：书面长句拆成两三个短句，允许口头连接词（"所以""那么""但是我要特别强调"）

> 反例（页面文字腔）："本页旨在说明两处方法学局限及其处理策略。"
> 正例（讲稿腔）："这两处我想先讲清楚，因为如果老师后面问到，我不想让它看起来像我漏了。"

## 五、违规扫描命令（复制即用）

```bash
cd "<vault>/科研"
f="<你的制作稿.md>"

# 1) 禁用短语扫描
grep -n "一句话总结\|最有价值的后续方向\|值得注意的是\|综上所述\|由此可见\|具有重要意义\|提供了新的视角\|奠定了基础\|至关重要\|深入探讨\|专家认为\|研究表明" "$f"

# 2) 无出处归因（人工确认是否有点名）
grep -n "研究表明\|专家认为\|有观点认为\|业内普遍认为" "$f"

# 3) 加粗密度（每页应 ≤3 处）
awk '/^## S/{page=$0; n=0} {n+=gsub(/\*\*[^*]*\*\*/,"&")} /^---$/{if(n>6) print page" → 加粗 "n" 处"; }' "$f"

# 4) 万能句式自查：抽 5 句页面文字，逐句问"能套到别的课题上吗"
```

## 六、终检评分（6 维 /60 分，<54 分返工）

| 维度 | 问自己 | 分 |
|---|---|---|
| **直接** | 是在陈述，还是在"宣告"？ | /10 |
| **节奏** | 句子长短有变化，还是每句一样长？ | /10 |
| **真实** | 读起来像人在组会上说话吗？ | /10 |
| **密度** | 有没有可以删掉而不丢信息的句子？ | /10 |
| **学术规范** | 归因具体、限定合理、口径清楚？ | /10 |
| **抗模式化** | 换成别的课题还能不能用？（能 = 低分） | /10 |

> 第 6 维是本地改造版。原 skill 的"抗检测性"对本场景不适用——**本场景的目标是让稿子真的有信息量**。

---

## 七、六条界限（改稿时不允许发生）

1. 数字被"概括化"（"p95 从 480ms 降到 160ms" → "明显优化"）
2. 事实关系被改（"展示了 X 的潜力" → "已采用 X"）
3. 条件、范围、否定、时态在改写中丢失
4. `[n]` 文献角标丢失或错位
5. 单位（kg / % / g / n / 例 / OR / HR）丢失
6. 不同队列的数字被并列比较

> 前 5 条是保真底线，第 6 条是口径规则。**任何"去味"改动违反界限，一律回退。**

---

## 八、噪声预算（反过度均质化）

借自 skill 的一条反直觉规则：**不要把每一页都改得一样干净。**

每千字允许保留 2–3 处轻微的不规整（比如一处程度较轻的过渡词、一组两项而非三项的并列）。全部消除会让整份稿子透出另一种"打磨过头"的痕迹。

**不保留**：`此案例印证了`、`具有重要意义` 这类高权重套话——直接删。

---

## 九、使用时机

```
① 内容稿定稿 → ①.5 去味关卡 → ①.6 待核清零 → ①.7 讲稿 → ② PPT制作稿 → ②.5 制作稿去味 → ③ 生成PPTX → ...
                     ↑                           ↑                          ↑
              全稿扫一遍（内容稿）           ⏳ 必须归零              逐页七项分场景过
              重点：页面文字 + 讲稿口径      （核到写字数 /           重点：⑥ 讲稿备注口语化
                                            核不到就删）             （= ①.7 的讲稿，此处精修）
```

> ⚠️ **①.6 不属去味**——它查的是**「哪些数还不知道」**，不是文字风格。
> 但**它必须排在 ①.7 之前**：**带着 ⏳ 写讲稿，等于把不确定性写成口播。**

> ⚠️ **①.7 讲稿在 ①.5 之后才产生**——它赶不上第一次全稿扫描。
> **它的去味落在 ②.5**（该表已把「⑥ 讲稿备注」列为**重力度**，正是为它留的位置）。
> 若讲稿在 ①.5 之前已有草稿，可两处都扫。

**为什么在这两处**：都还是纯文本，改一个字的成本是改 SVG 的几十倍便宜。AI 味是文字层问题，就该在文字层解决。
