# PPT 工具链速查

> **一句话**：**改样式只改 `ppt_style.py`，选版式看配方库，起一页从骨架库复制，出成品跑 `ppt_build.py`。**
>
> 📖 **完整手册见 [[PPT工具链手册]]** —— 本页只是速查；新项目怎么接、为什么这么设计、故障排查，
> 都在手册里。

## 一、五个部件

| 部件 | 位置 | 作用 |
|---|---|---|
| **① 数字** | `_scripts/ppt_style.py` | ⭐ **单一真相源**：配色 / 字号 / 边距 / 画布。**改 `ppt_style.py`，全库同步** |
| **② 零件** | `_scripts/ppt_kit.py` | SVG 组件：标题栏 / 卡片 / 色带 / 浅底块 / 数据卡片 / 箭头 / 花括号 / 占位框<br>⭐ 2026-09-22 新增：**带表头小卡片** `cardhead`/`cards_row` · **渐变** `grad_band`/`wash` · **装饰件** `badge`/`dot`/`rule`/`rulenum`/`iconslot` · **结尾页大标语** `statement` |
| **③ 配方** | `PPT版式配方库_20260915.md` | **32 个**版式配方（含出处、关键点、适用场景）+ 18 页映射表 |
| **④ 骨架** | `PPT骨架模板_20260915/` | **21 个**整页 SVG，复制即用。先看 `_预览总表.png` |
| **⑤ 管线** | `_scripts/ppt_build.py` | 一条命令：体检 → 预览 → PPTX → 成品验证 |

配套：`PPT视觉规范_国自然风格_20260915.md` v2（参数说明）· `汇报PPT产出流程手册.md` §四（操作规则）

## 二、日常工作流

```bash
# 1. 建项目（一条命令把目录约定与项目配置都建好）
python scripts/ppt_init.py 我的汇报 --title "…" --footer "…"

# 2. 起页：从骨架库挑一个，复制过去改名（文件名 = 页序）
cp <手册>PPT骨架模板_20260915/配方09_并列汇聚.svg 我的汇报/svg/01_xxxx.svg

# 3. 填内容：用 Write 工具改 SVG（或写脚本 import ppt_kit 生成）
#    删掉所有带 【说明】 的占位框和文字
#    骨架页脚是占位，用这条换成本项目的：
python scripts/ppt_build.py 我的汇报 --apply-footer

# 4. 出成品（一条命令跑完四步）
python scripts/ppt_build.py 我的汇报

# 单步重跑
python .../ppt_build.py 我的汇报 --only check    # 只体检（秒级）
python .../ppt_build.py 我的汇报 --only svg      # 只渲染预览
python .../ppt_build.py 我的汇报 --only pptx     # 只合 PPTX
python .../ppt_build.py 我的汇报 --only qa       # 只验成品
```

**产出**：`我的汇报/out/{preview,pptx,render}/`

## 三、常用操作

### 换主色（全库）

改 `ppt_style.py` 里的 `C["main"]`，然后：

```bash
python _scripts/make_svg_skeletons.py        # 重生成骨架
# 渲染预览 + 拼接预览总表（见骨架目录 README）
```

**浅底 `C["tint"]` 要跟着改**：主色提亮到 10–12%（原做法见 `ppt_style.py` 注释）。

### 改字号

改 `ppt_style.py` 的 `PT` 字典（**单位是 pt，文档口径**），`PX`（SVG 口径）自动派生。

> ⚠️ **字号 pt/px 换算是踩过坑的地方**：1600px 画布 = 13.333in = 960pt，**1 pt = 1.6667 px**。
> 规范文档写 pt，SVG 里必须写 px。曾经把「页面标题 32」当 px 用，做出来的标题比模板**小一半**。

### 新增一个骨架

在 `make_svg_skeletons.py` 的 `BASES` 或 `VARIANTS` 里加一条 → 跑生成 → 渲染 → 更新骨架目录 README 的两张表。

### 拆解别的参考模板

```bash
python _scripts/render_templates.py          # PPTX → 逐页 PNG + 联系表缩略图墙
```
改脚本里的 `BASE` 指向你的模板目录。

## 四、质检（`ppt_check.py`）

```bash
python _scripts/ppt_check.py <svg文件或目录>
python _scripts/ppt_check.py <目录> --strict        # 有 ERROR 退出码 1
python _scripts/ppt_check.py <目录> --json out.json

# ⭐ 跨文档口径核对（不需要传路径）：改过文档/增删脚本或配方后跑一次
python _scripts/ppt_check.py --docs
```

| 查什么 | 判据 |
|---|---|
| **A 占位残留** | 含 `【说明】` —— 骨架正常，成品页应清零 |
| **B 画布/边距** | 1600×900；左右边距均 = 61（**含虚线框**）<br>⚠️ 无栏页（`slide(cover=True)`）豁免 |
| **C 越界** | 元素/文字超出画布 |
| **D 调色板** | 颜色是否越出 `ppt_style.PALETTE` |
| **E 字号** | `font-size` 是否在字号表内 |
| **F 图片缩放比** | < 0.5 时警告（判据 C 的可自动化部分：图内字缩到幻灯上 < 9px 即不可读）|
| **G 固定件** | 是否缺标题栏 / 页脚（无栏页豁免）|

**成品像素体检**另由 `render_and_qa_pptx.py` 做（边缘污染 / 内容包围盒 / 留白）。

### `--docs` 跨文档口径核对

检查**脚本数 / 配方数 / 骨架数**在登记文档里的写法是否与实测一致：
（**只登记「应当写出数字」的位置**——已改为「指向单一出处」的文档不再登记）

```
实测：scripts 25 ｜ recipes 31 ｜ skeletons 20
  ✅ 脚本数  _scripts/README.md             写 25，应为 25
  ✅ 配方数  科研工作总览.md                写 31，应为 31
  ...
✅ 全库口径一致
```

**什么时候跑**：增删脚本、增删配方、生成新骨架之后。
**为什么需要**：脚本数、配方数、骨架数以前分散在 5–6 个文件里靠人工同步，**已经漏过两次**。
现在由脚本盯，不靠记性。

## 五、目录约定

```
<项目>/
  svg/           ← 页面（文件名排序 = 页序）        【你维护】
  images/        ← 图片资源                        【你维护】
  spec_lock.md   ← 首次运行自动生成（从 ppt_style） 【自动】
  out/
    preview/     ← SVG 逐页 PNG                    【自动】
    pptx/        ← 成品 PPTX                       【自动】
    render/      ← PPTX 逐页 PNG（验证用）          【自动】
```

**为什么需要 `spec_lock.md`**：ppt-master 的导出器要求显式声明 PPT 结构模式。
我们的页面是自由设计，用 `pptx_structure.mode: flat`（所有对象留在 Slide 本地，不建 Master/Layout）。
管线会**自动生成**，不用手写；改了 `ppt_style` 重跑即更新。

## 六、⭐ 导出兼容性：三条最易踩的

> **最重要的一条**：导出器遇到不支持的写法**不是降级，是直接报错**，
> 而且**一页失败整册导不出**。

| 想做什么 | ❌ 不能这么写 | ✅ 应该这样 |
|---|---|---|
| **竖排文字** | `writing-mode="tb"` | **`ppt_kit.vtext()`**（逐字堆叠）|
| 行距 | `line-height` | 手动排 `<text>` 的 `y`（行距 = 字号 ×1.5~1.7）|
| 上下标 | `baseline-shift` | 手动调 `y` + 换小字号 |

**完整清单**（28 项禁用属性 / 11 个可用元素 / filter 与 clip-path 的限制 /
🔴 **字重只有 2 档**的硬约束）→ **见 [[PPT工具链手册]] §七**。

## 七、讲稿备注（已打通，一条命令）

导出器**默认读 `<项目>/notes/`**，把内容写进 PowerPoint **备注栏**（已实测）。

### 7.1 从讲稿一键生成

```bash
python _scripts/make_notes.py <讲稿.md> -o <项目>/notes --match-svg <项目>/svg
```

- `--match-svg` 会**按数字前缀**把备注对上已有的 svg 文件名，保证一一对应
- 讲稿需要 `## NN · 标题` 形式的分页标题（我们的讲稿本来就是这个格式）
- 自动洗掉 `**粗体**`、`*斜体*`、`---` 分隔线（备注栏是纯文本，标记会露出来）
- **默认保留** `【停顿】【翻页】` 舞台提示（给人看有用）；要 TTS 时加 `--drop-stage`
- **默认排除**「备用」页（它不在片子里）；要包含加 `--with-backup`

产出 `notes/01_封面.md` … `notes/16_交叉空白….md`，导出时自动进备注栏。

### 7.2 用途

讲稿目前是**另开的 md 窗口** —— 讲的时候要来回切。写进备注就跟着 PPT 走，
彩排和答辩时直接在备注栏看。

### 7.3 写备注的注意（借自 ppt-master 的讲稿规范）

- **纯口语文本**。若要用于 TTS，不要残留 `[Pause]`、`①`、"要点："、"时长：" 这类标记
- 中文数字读起来更自然：「百分之六十八」优于「68%」
- 过渡句写在**开头句内**（"接下来……"），不要用 `[过渡]` 标记
- **多页定稿后一次性成篇**，别逐页写 —— 批量写才能让页间过渡连贯

## 八、常见故障

| 现象 | 原因 / 处置 |
|---|---|
| **渲染失败（未生成输出）**，浏览器无任何输出 | ⚠️ **最常见**：系统浏览器正开着，headless 调用被转发给已有实例后直接 rc=0 退出。<br>**已修**：`render_svg.py` 现在优先用 **Playwright 专用 headless shell**（独立二进制，不冲突）。<br>排查命令：`python render_svg.py --which` 看选中了哪个 |
| `release SVG export requires ... spec_lock.md` | 缺 `spec_lock.md` → 重跑 `--only pptx`（会自动生成）|
| **`unsupported text property 'xxx'`** | 用了 6.1 禁用的属性。跑 `ppt_check.py` 会直接指出是哪一页哪个属性 |
| SVG 里图片显示成空白/色块 | 相对路径失效。`render_svg.py` 会自动绝对化；手写时确认 `href` 是相对路径 |
| 中文变方框 | 用了 svglib/cairosvg。**必须用 `render_svg.py`**（走浏览器字体引擎）|
| 渲染报 QQBrowser / task_manager 错误 | **是噪声不是失败**，判据是输出文件存在且非空 |
| PPTX 打开发现占位文字还在 | 交付前跑 `ppt_check.py`，`【说明】` 应清零 |
| 换主色后骨架没变 | 只改了 `ppt_style`，**没重跑 `make_svg_skeletons.py`** |

## 九、工具链的设计原则

1. **单一真相源**——数字只写一次（`ppt_style.py`），其他全部派生。
   在此之前配色/字号在三处各写一遍，已经导致过"改一处漏一处"。
2. **零件与整页分离**——`ppt_kit` 给零件，骨架给整页起点，配方库给"为什么这样摆"。
3. **能自动化的检查绝不靠眼睛**——`ppt_check` 查源（秒级），`render_and_qa_pptx` 查成品（像素级），人眼只做语义判断。
4. **编号解耦**——配方编号会增删，骨架编号是稳定小集，两者靠映射表挂钩，
   **不要让两套编号数值相等**（否则必然重演"改一处漏一处"）。

## 十、⭐ 与 ppt-master 的关系（2026-09-22 核实）

> **结论：本管线不能完全替代 ppt-master。它替代的是 ppt-master 的「写作层」，
> 而「合并层」至今仍靠 ppt-master。**

### 10.1 实际调用链

`ppt_build.py` 的 `_find_ppt_master()` 定位合并器 —— **多候选 + 环境变量，不再硬编码盘符**
（2026-09-22 改：原来写死绝对路径，换机器就断）：

```python
# 顺序：环境变量 PPT_MASTER → <skills目录> → <skills目录>
PPT_MASTER = _find_ppt_master()
```

`stage_pptx()`（约 155–181 行）做三件事：

| 步 | 做什么 | 为什么 |
|---|---|---|
| 1 | 检查 `svg_to_pptx.py` 是否存在 | 缺了**直接失败**，报「ppt-master skill 未安装或被移动」 |
| 2 | 由 `ppt_style.py` **生成 `spec_lock.md`** | 头部写 `<!-- ppt-master-schema: spec-lock/v1 -->`——**按 ppt-master 的 schema** |
| 3 | 建 `svg_output/`（软链到 `svg/`） | **svg_to_pptx 约定读 `svg_output/` 目录** |

→ **`stage_pptx()` 就是"结合点"**：样式系统（自建）与合并引擎（ppt-master）由 `ppt_build.py` 焊在一起。

### 10.2 谁覆盖谁

| 层 | 谁做 | 状态 |
|---|---|---|
| 版式语言（配色/字号/边距） | **自建** `ppt_style.py` | ✅ 比 ppt-master 更适合我们的场景 |
| 版式配方（怎么摆） | **自建** 32 配方 + 21 骨架 | ✅ 独有 |
| 源文件质检（占位/越界/调色板/字号） | **自建** `ppt_check.py` | ✅ 更贴国自然规范 |
| 成品像素体检 | **自建** `render_and_qa_pptx.py` | ✅ |
| 预览渲染 | **自建** `render_svg.py` | ✅ |
| **SVG → PPTX 合并** | ❌ **ppt-master** | 🔴 **未替代** |
| 讲稿备注 → PPTX 备注页 | ❌ 借 ppt-master 规范（§七） | 🟡 部分 |

### 10.3 ppt-master 还有、我们**没有**的能力

> 以下能力目前**完全没用上**。记在本页，免得需要时才发现。

| 能力 | ppt-master 脚本 |
|---|---|
| **图片**：AI 生图 / 图库检索 | `image_gen.py` · `image_search.py` · `image_backends/` · `image_sources/` |
| **公式**：LaTeX 渲染 | `latex_render.py` |
| **动画 / 转场** | `pptx_animations.py` · `pptx_transitions.py` · `pptx_effects.py` |
| **旁白**：讲稿转语音并嵌入 | `notes_to_audio.py` · `tts_backends/` · `native_narration_pptx.py` |
| **填原生模板** | `template_import` · `template_fill_pptx.py` |
| **强化已有 PPTX** | `native_enhance_pptx.py` · `pptx_intake.py` |
| **PPTX 反解回 SVG** | `pptx_to_svg.py` |
| 图标资产 | `icon_sync.py` · `extract_svg_assets.py` |
| 图表 | `chart_recall.py` |
| 项目工作区 + 确认门 UI | `project_manager.py` · `confirm_ui/` |

**对我们的实际影响**：学术组会 PPT 默认**纯文字+表格、无配图**，所以图片/动画/旁白这几项暂时用不上。
**但一旦要配图**（机制示意图、数据图），得另外走 `nature-figure` / `scipilot-figure-skill`，或在 ppt-master 里做。

### 10.4 ⚠️ 两个存续风险

| # | 风险 | 说明 |
|---|---|---|
| 1 | **硬编码绝对路径** | `ppt_build.py:41` 写死 `Data\Skills\ppt-master\...`。**ppt-master 一旦被移动、卸载、或改名，管线在合并步骤直接断**，报错信息是"要重装 ppt-master" |
| 2 | **依赖 ppt-master 的内部约定** | `spec_lock.md` 的 schema（`spec-lock/v1`）、`svg_output/` 目录名，都是**它的内部实现**。它版本升级改了这些，合并会静默出错 —— `v1` 这个版本号就是标记 |

**建议（未执行）**：把 `PPT_MASTER` 路径改成环境变量 + 多候选探测，
并在 `ppt_check.py --docs` 里加一条「合并器可达性」自检。**改动前需确认。**
