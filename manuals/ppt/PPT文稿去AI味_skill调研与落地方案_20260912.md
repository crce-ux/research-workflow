## 结论（先看这段）

1. **榜单里对你真正有用的只有 1 个**：`shuorenhua`（说人话，MrGeDiao）。其余 9 个要么与它功能重叠，要么方向不对。
2. **你不需要装榜单第 1、2、3 名**。本地已有的 `writing-anti-ai`（当前处于关闭状态）在其 SKILL.md 第 229 行自述：*"Merges content from humanizer, humanizer-zh, and stop-slop skills"* —— 它本身就是榜单前三名的合并版。
3. **你最大的缺口不在 skill，在流程**。`汇报PPT产出流程手册.md` §八 记录过实战返工原因"AI 味重 ← 讲稿备注写成书面语"，但六步流程里**没有去味关卡**；唯一相关的是 §三 每页必查清单第 10 项"整体气质"，它已在视觉验证阶段，改稿成本最高。
4. **真正该做的三件事**：① 在流程 ①→② 之间插一个"去味关卡"；② 装 1 个 `shuorenhua` 用于中文改写；③ 把 `nature-paper2ppt` 已内置的 de-template 规则抽出来变成 PPT 专用的可执行清单（本文附录 A）。
5. **实测你的文稿 AI 味并不重**：科研库全库扫描 13 个高危短语，命中 3 个（`不是…而是…` 44 次、`一句话总结` 3 次、`此外` 4 次、`值得注意的是` 2 次），其余 9 个为 0。抽样看 `不是…而是…` 的实例（如"我们不是不能做，而是要诚实""不是药物本身，而是疗效的不可预测"）属**有力学术表达，不是 AI 味**。所以这是个"防止劣化"的问题。

### 单推 shuorenhua 的理由

对上你的场景，它是唯一四项全中的：

| 它的机制 | 对上你的哪条规则 |
|---|---|
| **改写前先锁定事实**：数字指标、版本编号、因果条件、责任归属一律保留 | 手册 §二 制作稿规则：数字不凭记忆、单位必须保留、文献编号必须保留、口径不混用 |
| **annotation mode 只标注不改写** | 可以先做"AI 味体检"而不动稿子，适合敏感性高的 S11 诚实页这类页面 |
| **scope 三档力度**：`structural` / `bounded`（长文默认，疑似空话归入"建议删除（待确认）"清单）/ `in-place`（不删整句，仅句内替换） | 学术文稿要的是 `bounded` 或 `in-place`，**绝不接受自作主张删句** |
| 中文优先，210+ 中文短语 + 25 类结构反模式 + 120 条 benchmark，误杀率门槛 <10% | 你的产出全是中文，且"误杀正常学术表达"是最大风险 |

补充：它还在 FAQ 里明确声明"不以绕过 AI 检测算法为设计目标"——学术伦理上站得住。

### nature-paper2ppt 的 de-template 规则（本地最强资产）

它直接给了 PPT 场景的**禁用短语黑名单**（除非原文引用，否则不得出现在标题/要点/讲稿中）：

```
一句话总结        最有价值的后续方向      不是……而是……
不只是……更是……    值得注意的是           总的来说
从某种意义上      提供了新的视角          具有重要意义
未来可以进一步探索
```

以及一条**可执行的判据**：

> 补：改写范式
> — Weak：一句话总结：该方法具有重要意义。
> — Better：该方法把检索、证据补全和答案生成拆成可审计流程，降低了遗漏关键文献的风险。
>
> **If a sentence sounds like it could fit any paper, rewrite it until it names the method, dataset, mechanism, figure evidence, or limitation from this paper.**
> （如果一句话能套到任何一篇论文上，就重写它，直到它点名了本文的方法、数据集、机制、图表证据或局限。）

这条判据就是科研 PPT 去味的核心算法。

## 三、落地方案

### 3.1 改流程：在 ① 与 ② 之间插"去味关卡"

现流程：

```
① 内容稿定稿 → ② PPT制作稿 → ③ 生成PPTX → ④ 视觉验证 → ⑤ 成品复核 → ⑥ 迭代
```

问题：AI 味要到 ④ 视觉验证（看 PNG）才被发现，届时改一页要动 SVG、重导出、再验证。

建议改为：

```
① 内容稿定稿 → ①.5 去味关卡 → ② PPT制作稿 → ②.5 制作稿去味 → ③ 生成PPTX → ④ 视觉验证 → ⑤ 成品复核 → ⑥ 迭代
```

**插在 ①.5 和 ②.5 的理由**：这两个位置都还是**纯文本**，改一个字的成本是改 SVG 的几十倍便宜。AI 味是文字层问题，就该在文字层解决。

**去味关卡的固定动作**（三步，见附录 A）：
1. **扫描**：过一遍禁用短语黑名单 + 五个高危句式
2. **判据筛**：逐句问"这句能套到别的论文/别的课题上吗？"能就重写
3. **分场景处理**：页面文字 → 用 `in-place` 力度（保守）；讲稿备注 → 允许 `bounded`（因为讲稿要口语化，本身就与书面语不同）

### 3.2 装 1 个 skill

```
install_source: skills.sh:mrgediao/shuorenhua/shuorenhua
```

用法约定（写进手册，避免每次重新交代）：
- 页面文字（标题/要点/图注/表格文字）：`in-place` 力度，**只改词不改句，数字与 `[n]` 角标原地保留**
- 讲稿备注：`bounded` 力度，目标是口语化
- 敏感页（如诚实页、局限页）：先用 annotation mode 只标注，人工确认后再改

### 3.3 抽一份 PPT 专用去味清单

见附录 A。建议把附录 A 独立成 `<手册>PPT文稿去味清单.md`，让每次做 PPT 时可直接引用，不必翻本报告。

### 3.4 不建议做的事

- ❌ 不要一次装多个去味 skill —— 规则冲突时模型会随机选一套，输出不稳定
- ❌ 不要用 AI 检测器给稿子设通过门槛 —— 误报会让正常学术表达被误改
- ❌ 不要为了"去味"引入第一人称、个人情绪、口语乱序（humanizer 原版的逻辑）—— 组会汇报不是博客

## 附录 A：PPT 文稿去味速查清单

### A1. 禁用短语（除非引用原文）

```
一句话总结        最有价值的后续方向      不是……而是……
不只是……更是……    值得注意的是           总的来说
从某种意义上      提供了新的视角          具有重要意义
未来可以进一步探索  奠定了基础             深入探讨
至关重要          此外（句首连用）
```

> 注：`不是……而是……` 在学术论证中**有时是必要的**（区分两个竞争假设时）。判据：如果它承担的是"排除竞争解释"的论证功能，保留；如果只是修辞上的"先立后破"节奏，删掉。

### A2. 五个高危句式（科研 PPT 重灾区）

| 句式 | 症状 | 改法 |
|---|---|---|
| **空泛评价** | "具有重要临床意义""为该领域提供了新思路" | 换成具体：效应量多少、样本量多少、改变了哪个决策 |
| **万能句式** | 一句话能套到任何论文上 | 点名本文的方法/数据集/机制/图表证据/局限 |
| **排比三连** | "快速、准确、可靠" | 用含义需要的数量，不要凑三 |
| **总结腔** | 每节末尾加一句升华 | 删掉，让最后一个具体事实结尾 |
| **模糊归因** | "研究表明""专家认为" | 点名：作者年份 + `[n]` 角标 + PMID |

### A3. 分场景力度（对应 PPT 制作稿七项）

| 制作稿项 | 力度 | 特别注意 |
|---|---|---|
| ① PPT 标题 | `in-place` | 标题是信息量最高的位置，宁短勿修饰 |
| ③ 页面文字 | `in-place` | **数字、单位、`[n]` 角标原地不动** |
| ④ 表格数据 | **不动** | 表格只查口径，不做文风处理 |
| ⑤ 图注 | `in-place` | 必须写清口径（哪个人群、哪个指标、什么单位） |
| ⑥ 讲稿备注 | `bounded` | 目标口语化；这条是实战返工的头号原因 |
| ⑦ 口径提醒 | **不动** | 防失真内容，禁止改写 |

### A4. 终检评分（借自 stop-slop，中文化）

逐维打 1–10 分，总分 <35 需返工：

| 维度 | 问自己 | 分 |
|---|---|---|
| **直接** | 是在陈述，还是在"宣告"？ | /10 |
| **节奏** | 句子长短有变化，还是每句一样长？ | /10 |
| **信任** | 有没有把读者当外行反复解释？ | /10 |
| **真实** | 读起来像人在组会上说话吗？ | /10 |
| **密度** | 有没有可以删掉而不丢信息的句子？ | /10 |

### A5. 界限（改稿时不允许发生）

1. 数字被"概括化"（"p95 从 480ms 降到 160ms" → "明显优化"）
2. 事实关系被改（"展示了 X 的潜力" → "已采用 X"）
3. 条件、范围、否定、时态在改写中丢失
4. `[n]` 文献角标丢失或错位
5. 单位（kg / % / OR / HR / RR）丢失
6. 不同队列的数字被并列比较

> 前 5 条借自 shuorenhua 的"保真回读"原则，第 6 条是本地手册的口径规则。

### C2. 它的规则构成（逐行读完 SKILL.md）

- **16 个模式**：内容层（理论起笔、案例印证结尾、首先其次再次、被动分析套话、模板化问题陈述、三元对称、段末总结句、模糊归因、填充短语、泛化结论）+ 语言层（AI 高频词表、系动词回避、过度对仗、三步走）+ 风格层（破折号、加粗）
- **7 条强制硬约束**（命中即失败）：AI 高频词每段 ≤2、段末套句全文 ≤1、三元并列每段 ≤1、理论起笔 ≤20% 段落、正文加粗 ≤5、泛化结尾 0、模糊归因 0
- **默认两步流程**：先出 100 字内风险识别报告（含命中模式编号 + 硬约束情况），**等确认后再改写**——与"先标注后改"的诉求吻合
- **噪声预算**：每千字允许保留 2–3 处轻微 AI 特征，理由是"全部消除会因过度均质化触发另一类检测"
- **质量评分 6 维 /60 分**
