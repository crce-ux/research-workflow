# PPT 工具链手册

> **这份是手册**（讲清怎么用、为什么这么设计）。
> **要一页速查**看 [[PPT工具链速查_20260915]]。
>
> **面向复用**：本工具链**不服务单一项目**。所有项目专有内容（页脚文字、受众、标题）
> 都放在**项目目录**里，共享库 `ppt_style.py` 不含任何项目专有串。

---

## 〇、30 秒上手

```bash
# 1. 建项目（一条命令，把目录约定和配置都建好）
python scripts/ppt_init.py 我的汇报 \
       --title "XXX 组会汇报" --footer "XXX · 组会汇报"

# 2. 起页：从骨架库复制一个 .svg 过去改名（文件名 = 页序）
cp <手册>PPT骨架模板_20260915/配方30_带表头卡片.svg 我的汇报/svg/01_xxx.svg

# 3. 填内容（Write 工具改 SVG；删掉带【说明】的占位框）

# 4. 出成品（体检 → 预览 → PPTX → 成品验证，一条命令）
python scripts/ppt_build.py 我的汇报
```

**产出**：`我的汇报/out/{preview,pptx,render}/`

## 一、架构：五个部件 + 一条管线

```
  ppt_style.py          ppt_kit.py            PPT版式配方库.md
  （数字 · 真相源）  →  （零件 · SVG 片段）→  （为什么这样摆）
        ↓                     ↓
  make_svg_skeletons.py  你的页面脚本
        ↓                     ↓
  PPT骨架模板_*/  ──复制──→  我的汇报/svg/*.svg
                              ↓
                       ppt_build.py（体检→预览→合并→验证）
                              ↓
                          out/pptx/*.pptx
```

| 部件 | 位置 | 你什么时候动它 |
|---|---|---|
| **① 数字** | `_scripts/ppt_style.py` | **改配色 / 字号 / 边距**——只改这里 |
| **② 零件** | `_scripts/ppt_kit.py` | 要新组件时才动；日常只**调用** |
| **③ 配方** | `PPT版式配方库_20260915.md` | **选版式**时查（32 个） |
| **④ 骨架** | `PPT骨架模板_20260915/` | **起页**时复制（20 个） |
| **⑤ 管线** | `_scripts/ppt_build.py` | 每次出成品跑 |

**核心原则：单一真相源。** 配色/字号/边距**只写一次**（`ppt_style.py`），
其余全部派生。改一处，重跑生成器，全库同步。

## 二、新项目怎么开始（5 步）

### 第 1 步 · 建目录

```bash
python _scripts/ppt_init.py <项目目录> --title "…" --footer "…"
```

产出：

```
<项目>/
  svg/          ← 页面（文件名排序 = 页序）      【你维护】
  images/       ← 图片                          【你维护】
  ppt.json      ← 项目配置（页脚/受众/目标）      【可改】
  build.md      ← 本册说明                       【可改】
  README.md     ← 项目内速查                     【参考】
```

### 第 2 步 · 写 `ppt.json`

**项目专有内容都放这里**，不要写进共享库：

```json
{
  "footer":    "屏状核 × 氯氮平 · 组会汇报",
  "audience":  "精神医学研究者 / 课题组成员 / 导师",
  "objective": "汇报研究现状、交叉空白与可检验的设想",
  "message":   "一句话核心信息"
}
```

`footer` 会被 `--apply-footer` 用来替换骨架的占位页脚；
`audience` / `objective` / `message` 写进 `spec_lock.md`。

### 第 3 步 · 起页

从 `PPT骨架模板_20260915/` 挑一个（先看 `_预览总表.png`），复制到 `svg/`，
**文件名加 `NN_` 前缀定页序**。

> **不知道选哪个** → 打开 `PPT版式配方库_20260915.md`，按"适用场景"找。
> 配方 30（带表头小卡片）和配方 17（数据卡片）是两个高频起点。

### 第 4 步 · 改页脚

骨架页脚是**占位** `（项目名）· 汇报`。两种改法：

```bash
# 一键：把占位换成 ppt.json 的 footer（只替换恰好等于占位的条目）
python _scripts/ppt_build.py <项目> --apply-footer
```

或手动改 / 在生成页面的脚本里 `from ppt_kit import set_footer; set_footer("…")`。

> ⚠️ 不处理的话，管线每次都会提醒，交付出去就是一行"（项目名）· 汇报"。

### 第 5 步 · 出成品

```bash
python _scripts/ppt_build.py <项目>              # 全流程
python _scripts/ppt_build.py <项目> --only check # 只体检（秒级，改一页时用）
python _scripts/ppt_build.py <项目> --only svg   # 只渲染预览
python _scripts/ppt_build.py <项目> --only pptx  # 只合 PPTX
python _scripts/ppt_build.py <项目> --only qa    # 只验成品
```

## 三、日常工作流

> **命令见 [[PPT工具链速查_20260915]] §二**；本节只讲**为什么这么走**。

```
① 内容稿定稿 → ② 制作稿（逐页素材）→ ③ 出页（复制骨架 + 填）→ ④ 出成品 → ⑤ 视觉验证 → ⑥ 迭代
```

**② 制作稿是关键中间产物**：把**内容**与**排版**解耦。逐页写清"这一页放什么"，
再决定用哪个骨架。跳过这步会边填边改版式，返工量翻倍。

**④ 与 ⑤ 是两个动作，别混**：
`ppt_build.py` 出的是**机器判据**（越界 / 越色 / 占位残留），
成品好不好看还得**人眼看渲染图**（原生视觉读 `out/render/*.png`）。
两者互为补充——机器查不出"这页没分量"，人眼查不出"这个颜色不在调色板里"。

## 四、组件速查（`ppt_kit`）

### 固定件

| 组件 | 用途 |
|---|---|
| `slide(title, body, num, page, note, footer_left, cover)` | 整页外壳。`cover=True` = 封面/结尾页（无标题栏无页脚） |
| `titlebar(title, num)` | 顶部标题栏 |
| `footer(page, left)` | 页脚 |

### 区块

| 组件 | 用途 |
|---|---|
| `band(x,y,w,text,h)` | 色带表头 / 结论条 |
| **`cardhead(x,y,w,h,title,lines)`** ⭐ | **带表头小卡片**——模板内容区主力形态 |
| **`cards_row(y,h,items,gap)`** ⭐ | 把 N 个 cardhead 横向排开（等宽等距） |
| `card(x,y,w,h,title,lines)` | 老式卡片（主色细边框 + 白底） |
| `tintbox(x,y,w,h,label,value)` | 浅底强调块（关键数值） |
| `bigstat(x,y,w,h,value,label)` | 数据卡片（大数字 + 小标签） |
| `capsule(x,y,w,h,text)` | 胶囊节点 |
| `statement(text,sub)` ⭐ | 结尾页大标语（147px） |

### 装饰件（**元素密度的来源**）

| 组件 | 用途 |
|---|---|
| `badge(x,y,text)` | 编号角标 |
| `dot(x,y,r)` | 色点 |
| `rule(x,y,w)` | 装饰短线 |
| `rulenum(x,y,list)` | 带色点的编号列表 |
| `iconslot(x,y,w,h)` | 图标位（占位，可换 `<image>`） |

### 渐变

| 组件 | 用途 |
|---|---|
| `grad_band(x,y,w,h)` | 色带淡出（主色 opacity 0→1） |
| `wash(x,y,w,h)` | 极淡色晕（opacity 0.10→0）——**给白底页纵深** |

### 连接件

`arrow(x1,y1,x2,y2)` · `brace(x,y1,y2)` · `leader(x1,y1,x2,y2)` · `ph(x,y,w,h,label)`（虚线占位框）

> **`ph()` 是占位框，交付前必须清零** —— `ppt_check` 会查。

## 五、骨架与配方选型

**21 个骨架** = 8 个基座（B1–B8，只有分区）+ 13 个配方变体（成型的整页）。

| 想做什么 | 看哪 |
|---|---|
| **定"这一页该删什么、该留什么"** | ⭐ `PPT版式配方库_20260915.md` **§受众速查（选择入口）** —— 按受众定取舍 |
| 一页要放什么、怎么摆 | `PPT版式配方库_20260915.md`（32 配方，含出处与关键点） |
| 直接拿一个能填的整页 | `PPT骨架模板_20260915/_预览总表.png` → 复制对应 `.svg` |
| 只有分区、格内自定 | `骨架_B1`–`B8` |

**三个高频起点**：

- **配方 30 带表头小卡片** —— 表格页改造。**把一个大表格拆成 2–4 块**，这是元素密度的直接来源
- **配方 17 数据卡片** —— 把关键数字从段落里提出来
- **配方 31 结尾页标语** —— 结尾页（无栏、大字）

### ⭐ 一条重要判断：丰富度靠"元素密度"，不靠大图

7 套国自然模板实测：**6/7 套的图片里 71–85% 是面积 <3% 的小件**（图标/编号/色点/装饰线）。
**真正差的是「页面上的元素个数」。**

判据（**删图测试**）：把某张图删掉，它旁边的文字是否**说不通**？
**说不通 = 论据；照样通 = 装饰。**

## 六、质检三关

| 关 | 工具 | 查什么 | 耗时 |
|---|---|---|---|
| **源** | `ppt_check.py` | 占位残留 / 画布越界 / **调色板越色** / 字号不在表内 / 缺固定件 / 导出器不支持的属性 / **对比度** | 秒级 |
| **成品** | `render_and_qa_pptx.py`（`ppt_build` 自动调） | 边缘污染 / 内容包围盒 / 留白 | 分钟 |
| **人眼** | 原生视觉读 `out/render/*.png` | 好不好看、读不读得出 | — |

```bash
python _scripts/ppt_check.py <svg目录>            # 体检
python _scripts/ppt_check.py <svg目录> --strict   # 有 ERROR 退出码 1
python _scripts/ppt_check.py --docs               # ⭐ 跨文档口径核对（改过文档/配方/骨架后跑）
python _scripts/ppt_check.py --contrast           # ⭐ 调色板对比度矩阵（改配色后跑一次）
python _scripts/ppt_check.py <svg目录> --fix --dry-run   # ⭐ 先看会改什么（建议先跑）
python _scripts/ppt_check.py <svg目录> --fix             # 出框自动修复（写前自动 .bak）
```

### 6.1 对比度检查（2026-09-26 新增）

**判据借用 WCAG 2.1**：正常字号 **≥4.5:1**，大字（≥24pt，或 ≥18pt 且粗体）**≥3:1**。
⚠️ PPT **没有**强制等效标准，**这是参考值，不是合规判定**。

**页脚豁免**：`C['foot']` 上的不达标只进 INFO（**不计入 WARN**）——
页脚低对比是有意设计（不喧宾夺主），若按 WARN 报会每页恒报一条。

**跳过两类**：占位文字（`【说明】`交付前会删，报了是噪声）；
底色为渐变/半透明的文字（底色是混合出来的，算不准 → 宁可漏报不误报）。

**取底色的规则**：在"含住文字起点"的矩形里，取**面积最小且有纯色填充**的矩形
（面积最小 ≈ 最贴近文字的一层）。

> **实测发现（2026-09-26，跑全部 21 个骨架）**：
> - `weak #7A8698` 在白底仅 **3.69:1**，而它的用途正是**图注 / 导语**这类小字
>   （配方 28 的「所以」32px、配方 30 的导语条 32px、骨架 B4 的 23px 标签）
> - `#B9C4D2`（配方 1 章节过渡页里**非当前**章节的淡色文字）在白底仅 **1.77:1**
> - `foot #9AA5B4` 页脚 2.50:1 —— 有意为之，仅 INFO
>
> ⚠️ 上述三项**均为设计取舍，不自动修改**。要不要调色值属**视觉决策**，须人工定。

### 6.2 文字出框自动修复（`--fix`，2026-09-26 新增）

只做一件事：**把出框的文字降到「字号表内能放下的最大档」**。

🔴 **只降字号，不扩框。** 扩框会与邻元素撞车 —— 而脚本**看不到版式意图**
（哪根线必须对齐、哪个卡片和谁等宽）。**改一个自己看不出后果的几何，比不修更危险。**

**两道闸**：

| 闸 | 值 | 理由 |
|---|---|---|
| 字号下限 | `caption` = **23px** | 再小读不出来 |
| 降幅上限 | **30%**（`FIX_MAX_DROP = 0.70`）| 🔴 **40px 缩到 23px 不是「修复」，是重排** —— 说明文字本身就太长，正确答案是改措辞或扩大该框 |

**安全机制**：写前 `.bak_autofit` → 写完**复检** → 复检变差**自动回滚**并删 bak。
放不下的进「留人工」清单，理由写到可操作（区分「真放不下」与「降幅超限」两种）。

> ⚠️ **回滚分支在正常几何下跑不到**：降字号对文字宽度是单调递减的
> （容器只按文字起点选，不受字号影响），所以「改了反而更差」不会自然发生。
> 已用**故障注入**（令 `fit_size` 返回表外字号 37）**实测它确实触发、且逐字节还原** ——
> **跑不到的分支等于没测过**，安全网必须自己验一次。

**用例**：`_work/make_fixture.py` 造 4 个几何可控的样本（出框可修 / 出画布可修 / 真放不下 / 降幅超限），
`_work/test_rollback.py` 做回滚的故障注入测试。
> 为什么要造用例：**本库 21 个骨架均无出框（ERROR 0）** ——
> 在干净的库上跑 `--fix` 永远显示「无需修复」，**证明不了任何事**。


**`--docs` 为什么需要**：脚本数/配方数/骨架数以前分散在多份文档里靠人工同步，**已经漏过两次**。
现在由脚本盯，不靠记性。

> ⚠️ **成品像素体检会对封面/结尾页报"留白偏大"——属正常**（整页留白是设计）。
> 该检查看不到"无栏页"标记，故有此误报。

## 七、导出兼容性：什么能写、什么会炸

> **最重要的一条**：导出器遇到不支持的写法**不是降级，是直接报错**，
> 而且**一页失败整册导不出**。

### 7.1 会让导出失败的文字属性

```
writing-mode  line-height  dominant-baseline  baseline-shift  text-align
text-shadow   text-transform  white-space  word-spacing  word-break
font（简写）  font-variant  font-stretch  direction  unicode-bidi  …
```

完整清单在 `ppt_kit.UNSUPPORTED_TEXT_PROPS`。**最常见的三个**：

| 想做什么 | ❌ 不能这么写 | ✅ 应该这样 |
|---|---|---|
| 竖排文字 | `writing-mode="tb"` | `ppt_kit.vtext()` |
| 行距 | `line-height` | 手动排 `<text>` 的 `y`（行距 = 字号 ×1.5~1.7）|
| 上下标 | `baseline-shift` | 手动调 `y` + 换小字号 |

### 7.2 会失败的元素

只认 11 个：`rect` `circle` `ellipse` `line` `path` `polygon` `polyline`
`text` `image` `g` `svg`（＋ `text` 内的 `tspan`）。其余一律报错。

**`filter`** 只做阴影/发光，且**不能挂在 `<image>`/`<g>`/`<tspan>` 上**。
**`clip-path`** 只允许挂在 `<image>` 上。

### 7.3 已验证没问题的

```
stroke-dasharray 虚线 ｜ opacity ｜ tspan 加粗 ｜ ⭐ 线性/径向渐变
锚点变换 rotate ｜ <image> 内嵌 ｜ 中文 + 中英混排
```

### 7.4 🔴 硬约束：**PPTX 字重只有 2 档**

`svg_to_pptx` 把 `font-weight` 折成**布尔**（`≥600` 即粗）→ **900≡700、500≡300**。
实测：数字字重 300/500/900 **全部无效**。

- **中文字重只有「常规 / 粗」两档。** 多出的层次用**字号 / 颜色 / 底块**做。
- 浏览器端把 `Noto Sans SC` 提到栈首可拿 5 档可变字重，
  但 **ppt-master 会把它映射回 Microsoft YaHei** → **预览会骗人**。
  故本库字体栈保持 `Microsoft YaHei` 打头。
- **数字**可用 `ppt_style.FONT_NUM`（`'DIN Next LT Pro','Microsoft YaHei'`）——
  同段文字里数字走 DIN、中文走雅黑（模板 `1深蓝色系`/`6红色系` 同款）。

### 7.5 权威参考（在 ppt-master skill 里）

| 文件 | 内容 |
|---|---|
| `docs\zh\powerpoint-svg-mapping.md` | ⭐ **完整支持边界表**（中文，13 节），§4 文本 / §5 图片 / §6 填充线条效果 |
| `references\shared-standards-core.md` | §1.0 结构黑名单 + 内联属性白名单；§2 数值单位；§4.3 溢出判据 |
| `references\svg-effects.md` | §6.x 各效果的"能写什么" + "不支持时的替代做法" |

## 八、与 ppt-master 的关系

> **本管线不能完全替代 ppt-master。** 它替代的是 ppt-master 的**「写作层」**，
> 而**「合并层」至今仍靠 ppt-master**。

- `ppt_build.py` 调用 ppt-master 的 `svg_to_pptx.py` 做最终合并
  （路径由 `_find_ppt_master()` 探测：环境变量 `PPT_MASTER` → 两个已知技能目录；**不再硬编码**）
- 它由 `ppt_style.py` 生成 ppt-master schema 的 `spec_lock.md`，
  并把 `svg/` 链接成 `svg_output/`（该合并器约定读这个目录名）
- **自建覆盖：版式语言 + 配方骨架 + 源质检 + 成品体检。合并层仍靠 ppt-master。**

### ppt-master 还有、我们**没接**的能力

| 能力 | 脚本 |
|---|---|
| AI 生图 / 图库检索 | `image_gen` · `image_search` |
| LaTeX 公式渲染 | `latex_render` |
| 动画 / 转场 | `pptx_animations` · `pptx_transitions` |
| 讲稿转语音并嵌入 | `notes_to_audio` · `native_narration_pptx` |
| 填原生 PPTX 模板 | `template_fill_pptx` |
| 强化已有 PPTX | `native_enhance_pptx` |
| **PPTX 反解回 SVG** | `pptx_to_svg`（**已于 2026-09-22 用于反解国自然模板**，见 §十） |

**需要配图时**：走 `nature-figure` / `scipilot-figure-skill` 出图，
放进 `<项目>/images/`，页面里写 `<image href="../images/xxx.png">`。

| 现象 | 原因 / 处置 |
|---|---|
| **渲染失败（未生成输出）** | 系统浏览器正开着，headless 调用被转发。`render_svg.py` 已改用 Playwright 专用 shell；排查 `python render_svg.py --which` |

## 十、设计决策与改版历史

### 10.1 坐标从 `M`/`W` 派生（2026-09-22 修）

此前 18 个骨架把右边界**硬编码成 1560**（= `W-40`）。当 `G["margin"]` 由 40 改 61 时，
**12 处会越界**。这正是这套工具链要防的「**改一处漏一处**」。
现在改 `ppt_style.G["margin"]` 一处，重跑生成器即全库同步。

### 10.2 2026-09-22 视觉改版（依 7 套国自然模板反解）

| 项 | 改前 | 改后 | 依据 |
|---|---|---|---|
| **主色** | `#123E6B` | **`#0046A4`** | 7/7 套模板主色**全部高饱和**，旧的偏暗偏灰是异类 |
| **边距** | 40 | **61** | 7 套中位 **3.8%**×1600；我们 2.5% **低于全部 7 套下限** |
| **字号** | `cover` 54pt | `cover` 73pt + **新增 `statement` 88pt（147px）** | 模板 6/7 套字号上限**恰好 146px**；**结尾页比封面还大** |
| **浅底/边框** | — | 新增 `tint #E5EDF6` · `gray #F2F2F2` · `edge #D9D9D9` | 模板实测 `#F2F2F2` 35 处、`#D9D9D9` 124 处 |
| **骨架/配方** | 18 / 29 | **20 / 31** | 新增配方 30（带表头卡片）· 31（结尾页标语） |

**⚠️ 撤回的三项**（当时以为要改，实测证伪）：
边距改 4.7%（**单套**值）· 标题栏 72→96px（**3 套里 2 套根本没有标题带**）· 封面整页背景图（三种做法都有）

> 🔴 **方法学教训**：**指标必须人工验证定义**。
> 本次两个错误（"小图占比""顶部带高度"）都源于**拿未验证的指标下结论**。
> **异常值（如 166.8%）是"定义有问题"的信号，不是发现。**

### 10.3 复用时容易踩的三个坑

1. **不要把项目专有内容写进共享库**。页脚写 `ppt.json`，不要改 `ppt_style.FOOTER_TEXT`。
2. **不要硬编码绝对路径**。脚本一律从 `__file__` 推导或走 CLI 参数
   （已修：`make_svg_skeletons` 的 `OUT`、`ppt_build` 的 `PPT_MASTER`、`render_templates` 的 `BASE`）。
3. **不要绕过 `ppt_style` 直接写死颜色/字号**。`ppt_check` 会报越色，但只能事后发现。

### 10.4 ⚠️ 骨架里的**演示内容是「屏状核」的**

21 个骨架的**页面文字**（标题、表格行、示意图标签）用的是**屏状核课题的真实内容**当例子——
**属有意设计**（真实长度比"标题一/标题二"更能验证版式撑不撑得住）。

**复用时必须全部替换**。只有两处是参数化的、不用管：

- **页脚** → `ppt.json` 的 `footer`，跑 `--apply-footer` 自动换
- **页码/编号** → 生成页面时给

其余（标题行、卡片表头、示意图里的标签）都是示例文本，逐页改成你自己的。
