# 样例

## 五分钟看到它能干什么

```bash
python scripts/audit.py examples/bad.md
```

`bad.md` 是一份故意写错的稿件：排他性断言、空泛量词、缩写未展开、名词化、伪对立、引用编号对不上。运行后得到一张表：

```
  位置    检查项        问题                                依据
  L3      语言与断言    唯一：…                            排他性断言·未见出处
  L7      措辞          不是相关而是                        伪对立
  —       引用编号      [3]                                正文引用但文末缺失
```

四列含义：

| 列 | 内容 |
|---|---|
| 位置 | 行号；文件级问题写「—」 |
| 检查项 | 哪个检查器报的 |
| 问题 | 命中的词或具体差异 |
| 依据 | 触发了哪条规则 |

## 看机器可读的输出

```bash
python scripts/audit.py examples/bad.md --json
```

## 放进 CI 或投稿前流程

```bash
python scripts/audit.py 稿件.md --strict   # 有问题时退出码 1
```

## 说明

- 命中不等于要改。每条都要回原文核对，尤其是「数字-口径」这类只供人工判断的。
- 没跑的检查器会列在末尾，不会假装跑过。
