# 文献调研流程

## 读什么

- 定检索策略、报覆盖 → `references/coverage-and-rules.md`
- 建证据表 12 列 → `references/evidence-table.md`
- 领域字段矩阵（G0）→ `references/g0-field-matrix.md`
- 中文库 / 监管库 / 踩过的坑 → `references/pitfalls.md`、`references/regulatory-databases.md`

## 本 skill 补的是什么

现成的检索与精读 skill 已经很多。本 skill 补三块**它们没有的**：

1. **覆盖声明**——凡是核查，必须报出「**查了什么**」与「**没查到什么**」
2. **影响力指标的归一化读法**——裸被引数会把最好的新文筛掉
3. **证据表的列口径**——IF 标年份、分区标版本，**不写口径等于没写**

## 上下游接口

工序地图上本 skill 是 **A 段（文献侧）**，主链的起点。

**上游给我什么**

| 从哪来 | 交接物 | 具体是什么 |
|---|---|---|
| 课题本身 | 检索问题 | 要回答什么、边界在哪。A1 是本链起点，**没有上游 skill** |
| `paper-reading` | 精读笔记 | 已确定要精读的文献，15 列，含证据标签与定位方式；回填时对齐本 skill 的证据表 |

**我给下游什么**

| 交给谁 | 交接物 | 下游拿它做什么 |
|---|---|---|
| `ai-academic-writing` | **证据表（12 列）** + 覆盖声明 | 成文时每一个数字都要指回对应行；引用不得虚设 |
| `academic-slides` | 覆盖声明口径 | 被引图清点用的是同一个动作换了对象（N→M→K） |

**什么状态算交出去了**

证据表每一行都能追回一次检索（库 · 检索式 · 日期），覆盖声明写明 N→M→K。缺一样就不算交出去。

## 〇、A1 检索入口（**检索这一步只有一个入口——本文**）

> 🔴 **不要再维护第二份「该用哪个检索工具」的清单。** 要改就改本文 §〇。

### 常轨（默认走这条）

| 干什么 | 用什么 | 说明 |
|---|---|---|
| PubMed 检索 | 检索能力（PubMed 类 MCP / 网页） | 拆成 **2–3 个简查询**——复杂查询易超时 |
| 中英文补充 | 通用搜索 | 补 PubMed 覆盖不到的中文与灰色文献 |
| **中文库取数** | `scripts/cnlit_search.py` | ⚠️ 需本机重建 venv + 知网 cookie；**坑单见 `references/pitfalls.md` §五**（维普四坑 / 知网四坑 / 别外挂名单） |
| 元数据（卷期页） | `scripts/pubmed_meta_fetch.py` | 缺的**留空**，不硬填 |
| 存在性核验 | `scripts/verify_pmid_doi.py` | **G0 硬门禁** |
| 影响力排序 | `scripts/quality_screen.py` | **排序用，不淘汰** |
| **政务 / 产业库取数** | `references/regulatory-databases.md` | 见下「非常规数据源」——**不能 curl 拿** |

> 检索式与命中数**必须留档**——见 §一 覆盖声明。

### 检索式怎么构造

1. 从研究问题里**抽出核心概念**
2. 每个概念找**同义词与替代拼法**
3. 生物医学题：把概念映射到 **MeSH 词**
4. 拼布尔式：`(概念1 OR 同义词1) AND (概念2 OR 同义词2)`
5. 加字段限定提精度：`[Title/Abstract]` · `[MeSH Terms]` · `[Journal]`
6. **试跑再看**：命中 **>500** 条 → 加过滤器；**<10** 条 → 放宽词

> ⚠️ **中文期刊不在 PubMed / Crossref 索引里**——必须单独走中文库，
> 且**标为需人工核查**。**不能因为「PubMed 里没有」就当它不存在。**

### 来源分级与降级链

| 需求 | T1 首选 | T2 次选 | T3 兜底 |
|---|---|---|---|
| 医学 / 临床 | PubMed | Semantic Scholar | Google Scholar |
| 跨学科 | CrossRef | Semantic Scholar | Scopus |
| 预印本（CS / 物理） | arXiv | bioRxiv / medRxiv | — |
| 系统性综述 | PubMed + CrossRef + arXiv | bioRxiv / medRxiv | WoS / Scopus |
| **中文文献** | — | — | **CNKI / 万方（人工）** |

```
1  选出与题域匹配的 T1 源
2  并行查全部 T1
3  命中且相关度够 → 收
4  T1 耗尽或不足  → 升到 T2
5  T1+T2 都不行   → 升到 T3，并**明确告知「结果可能不全或过时」**
6  全部耗尽        → 返回部分结果 + 建议改检索式
```

> 🔴 **T3 命中必须带警告**——它们是抓取来的，响应格式没有契约。

### 非常规数据源（政务 / 产业库）

**以下数据源不能直接 curl 拿**：NMPA · CDE · 国家医保局 · 巨潮资讯 · 港交所披露易 · 卫健委。

```
❌ 已证伪：curl / requests · Playwright 无头 · 有头 + stealth
          · goto → reload 换 Cookie · 反混淆 api.js
✅ 唯一可用：DrissionPage + 本机真实浏览器（有头，经 CDP 接管真实进程）
```

| 站点 | 通路 | 关键点 |
|---|---|---|
| **NMPA** 批准文号 | DrissionPage + **localStorage 注入** | 首页搜索框驱动不了；**结果页可独立访问** |
| **CDE** 受理品种 | UI 驱动，**按回车提交** | 点「查询」按钮**不触发**；接口 URL 带一次性令牌 |
| **国家医保局** | ✅ **curl 直下** | 目录附件 PDF |
| **巨潮资讯** | ✅ 接口 | 先查表拿 `orgId`（**不是股票代码**） |
| **港交所披露易** | ✅ 接口 | 先 `prefix.do` 拿 `stockId` |
| **ClinicalTrials.gov** | ✅ **API v2 直连** | 不是非常规源——**别开浏览器** |

**两条纪律**（对任何「脚本代替人操作界面」都成立）：

1. **「不报错」≠「检索式生效」**——必须配对照组
2. **解析条数必须与站点标称的命中数对账**——漏解析不报错

> 🔴 **法定披露 ≠ 申报状态。**
> 上市公司公告**滞后**；「某药是否已申报」**以 CDE 受理目录为第一手**。
> 交易所只记「公司说了什么」，不记「事情发生了没有」。

逐站参数、返回结构、本机接线表见 [`references/regulatory-databases.md`](references/regulatory-databases.md)。

## 一、⭐ 覆盖声明（强制）

**凡是核查，都要能报出三个数**：

```
可识别位置总数 N  →  实际核查 M  →  未能覆盖 K（逐条列原因）
```

| ❌ 不合格 | ✅ 合格 |
|---|---|
| 「引用已全部核实」 | 「28 处引用中核实 26 处；2 处因付费墙未读取，标未核实」 |
| 「已逐篇核对数字」 | 「24 篇中核对 24 篇；其中 3 篇仅读到摘要，标证据深度=摘要」 |
| 「代理已复查」 | 「代理覆盖 D1/D3/D7/D8；D17 因源文件缺失未跑」 |

> 🔴 **只报「已检查」而不报「没检查什么」，等于假装覆盖完整。**

**四条细节**：

1. 正则 / 关键词搜索 **≠** 完整解析——无法解析的格式列为**覆盖缺口**
2. **未覆盖的部分仍算未核查**，不得默认通过
3. 读到的**深度要分级**（全文 / 摘要 / 前三页 / 仅标题）——**不同深度不能合并计数**
4. 计数须与记录对账

## 二、四条规则

**1. 相关度是门槛，影响力是排序。**
不能因为 IF 高就留一篇不相干的。

**2. 裸被引数不可用，必须按年份归一。**
实测：某 2026 年新文被引仅 **5 次**，但 **FWCI = 31.2、被引百分位 99.7%、Top 1%**。
**用裸被引会把最好的新文筛掉。**

**3. 影响力 ≠ 质量，而且「权威的错误更危险」。**
权威团队也会犯错，而**权威的错误没人质疑**。
**标出来，但仍以证据本身为准。**

**4. 外在不该覆盖内在。**
实测反例：某篇 FWCI 0.47、被引百分位 69.5%（**低于本领域同龄平均**）的论文，
对具体课题仍是**关键证据**。
→ **「对本课题关键」与「影响力高」是两件事，不要用一个否掉另一个。**

## 三、G0 · 检索层质控（四项硬性，不过不进表）

> G0 这道关装在**建表之前**。不装的话，脏数据已经进表了才发现。

| # | 项 | 怎么做 |
|---|---|---|
| 1 | **去重** | 跨源合并，按 DOI/PMID 唯一化；无 DOI 用「标题+年份+一作」 |
| 2 | **存在性** | **逐条回源反查** |
| 3 | **元数据完整** | 标题/期刊/年/卷期页；缺的**显式标注**，**不留空** |
| 4 | **版本** | 标记 `[预印本]`/`[正式版]`；同一研究**只留一版** |

> ⚠️ **第 2 项对 AI 协作尤其要紧**：AI 给出的 PMID/DOI **可能编造**。
> **一律回源核，不得凭信**，包括看起来眼熟的条目。

### ⭐ 先做最便宜的检查

**在跑多源交叉之前**，对每条有 DOI 的记录先请求 `api.crossref.org/works/<DOI>`：

- **404** → DOI 本身错了
- **200 但标题/作者对不上** → **DOI 张冠李戴**（指向了另一篇）

> 一条实测：35 条核查共 9 处错误，**7 处被 Crossref 反查抓到**。
> **最便宜的检查最先做。**

**第 3 项「元数据完整」的字段级判据与三级严重度**（什么算 🔴 / 🟡 / 🟢、
Early Access 漂移以谁为准、中文文献怎么标）见
[`references/g0-field-matrix.md`](references/g0-field-matrix.md)。

## 四、检索预算与上限（未声明时按最保守执行）

| 项 | 默认 | 说明 |
|---|---|---|
| 检索轮数 | 2–3 轮 | 超了仍无结果 → 记「未检出」并停，**不无限重试** |
| 重试次数 | 3 次 | 限流 / 超时；仍失败 → 记实际错误，**不隐瞒覆盖损失** |
| 独立代理轮数 | 2 轮 | 止损：6 轮不收敛即停 |
| 联网 | **需明确授权** | 未授权时**只读本地已有材料** |

## 五、流程骨架

```
Step 0  检索与筛选（多源并行 + 三级筛选 A/B/C）
   ↓
G0      质控四项（全过才进表）  ← ⭐ 本 skill 的重点
   ↓
Step 1  证据表（单一数据源）
   ↓
Step 2  逐篇讲解  ← 每个数字回原文对应语句核过
   ↓
Step 3  综述      ← 正文 [n] 与文末编号表一一对应
   ↓
Step 4  交给下游（PPT / 论文）
```

**单一数据源 + 单向数据流**：证据表是主数据源，讲解 / 综述 / PPT 全部与之对齐。
**任何修改先改证据表，再同步下游。**

## Anti-Patterns

- **Never** 只报「已检查」而不报「没检查什么」——必须给出 `N → M → K`
- **Never** 把未覆盖的部分默认通过
- **Never** 用裸被引数排序
- **Never** 采信 AI 给出的 PMID / DOI 而不回源核验
- **Never** 在元数据缺失处硬填数字——留空并标注「待确认」
- **Never** 因影响力低就否掉对本课题关键的证据——外在不覆盖内在
- **Never** 因作者是权威团队就跳过核查
- **Never** 在读取深度不分级的情况下合并计数
