# 踩坑清单

## 一、检索与质控

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **AI 给出的 PMID / DOI 直接采信** | **一律回源核**——AI 可能编造，包括看起来眼熟的条目 |
| 2 | **卷期页缺失时硬填** | 留空 + 标「待出版方确认」。**硬填的数字比空值危险得多** |
| 3 | **去重只按标题** | 按 DOI/PMID；无 DOI 用「标题 + 年份 + 一作」三件组合 |
| 4 | **预印本与正式版算两篇** | 同一研究**只留一版**，并标记版本 |
| 5 | **中文期刊查不到 DOI 就跳过** | 显式标注「中文期刊未注册 DOI」，不留空 |

## 二、筛选与排序

| # | 坑 | 正确做法 |
|---|---|---|
| 6 | **用裸被引数排序** | 用 **FWCI / 被引百分位**——裸被引会随发表年限增长 |
| 7 | **因为 IF 高留下不相关的** | 相关度是**门槛**，影响力是**排序** |
| 8 | **因为 FWCI 低就否掉关键证据** | 外在不覆盖内在——「对本课题关键」与「影响力高」是两件事 |
| 9 | **因为是大牛组就少查一遍** | 权威的错误更危险——标出来，仍以证据本身为准 |

## 三、建表与核查

| # | 坑 | 正确做法 |
|---|---|---|
| 10 | **IF 不标年份 / 分区不标版本** | `4.4 (2024 JCR)`、`中科院医学2区(升级版2025)`——**不写口径等于没写** |
| 11 | **不同读取深度合并计数** | 全文 / 摘要 / 标题**分开记**——摘要级结论不可用 |
| 12 | **只报「已检查」，不报「没查什么」** | 报出 `N → M → K`，K 逐条列原因 |
| 13 | **把「已核实身份」当成「内容支持」** | 文献存在 ≠ 它支持你所引述的内容 |
| 14 | **把二手陈述当一手证据** | 转引、元分析合并值、反推值，都要追到原文对应语句 |

## 三、最贵的一类问题：把二手当一手

实测中反复出现，且**代价最高**：

| 症状 | 例 |
|---|---|
| 把**转引**当原始研究 | 「综述称 X 研究发现了 Y」→ 直接写成「X 研究发现了 Y」，没读原文 |
| 把**元分析**当原始研究 | 引用 meta 的合并值，却当成某一项原始研究的结果 |
| 把**反推值**当文献值 | 自己从两个数字算出来的值，写成「文献报道」 |
| 把**同源团队**当独立证据 | 同一课题组的三篇论文，当成三条独立证据支撑「研究空白」 |

**共同点：没有回到原文核过。**

## 四、自检问法

收工前逐条问：

1. 「我报的覆盖数，能对着记录复算吗？」
2. 「没覆盖的部分，我列出来了吗？」
3. 「我的排序用的是归一化指标还是裸被引？」
4. 「有没有一条结论，是从摘要读出来的？」（有 → 标出来或读全文）
5. 「设计书里每条依据，我能指到证据表哪一行？」
6. 「支撑『研究空白』结论的，是几条**独立**证据？」

## 五、中文库（维普 / 知网）——`cnlit_search.py`

> 中文期刊不在 PubMed / Crossref 索引里，必须单独走中文库。
> **英文库的检索式习惯不能直接搬过来**——中文库的解析器是另一套。

### 两条通用纪律 ⭐

**以下两条通用纪律对任何「脚本代替人操作界面」都成立，跌过一次就别再跌第二次。**

1. **「不报错」≠「检索式生效」**——**必须配对照组**（单概念命中数）验证。
   > **实测**：维普裸词 **静默返回与检索词完全无关**的通用最新列表，不报错。
2. **解析条数必须与站点标称的「命中 N 条」对账**——对不上就是漏解析，**且不报错**。
   > **实测**：只匹配题名一种写法时 **87 条解析出 67 条，不报错**。

### 维普 · 四个坑

| # | 坑 | 正确做法 |
|---|---|---|
| V1 | **裸词检索** | **必加字段前缀**：`M=`（篇名）或 `U=`（任意字段）。裸词静默给无关结果 |
| V2 | **用 `M=` 前缀拼布尔式**（`M=A AND M=B`） | 🔴 **解析器不认，会静默假阳性**。**要交叉就用库内交叉检索**，别拼布尔 |
| V3 | **翻页 / 筛选走 URL 参数** | 🔴 **URL 参数一律无效，只能点 UI 元素**——维普把结果集状态放前端 |
| V4 | **指望一次检索拿到交集** | **单概念式全量取回 → 本地筛查求交**（因为 V2、V3 堵死了别的路） |

> ⭐ **贯穿维普的一条规律**：凡是「**结果集的二次操作**」（翻页、筛选），
> **URL 参数一律无效**。见到一个新参数，先默认它无效，再去验。

### 知网 · 四个坑

| # | 坑 | 正确做法 |
|---|---|---|
| K1 | **题名单元格只匹配一种写法** | 有两种写法（带链接 / 纯文本）——**两种都匹配**，否则静默漏 1/3 |
| K2 | **检索后读 URL** | 检索是 **AJAX，URL 不变**——**读 DOM / 监听响应**，别读 URL |
| K3 | **以为不需要登录** | 首次**必须人工过一次滑块**（一次性）；cookie 存进 profile 后长期有效 |
| K4 | **`--attach` 模式下让脚本 `quit()`** | 🔴 **绝不 quit** ——它已由人工验证过，关掉就得重过滑块 |

> ⭐ **知网比维普强的地方**：知网「**主题**」字段 = 题名 + 关键词 + **摘要**。
> 所以**库内交叉检索能命中本地筛查查不到的层**——**能用就用**。

### 质量过滤：用库自带的，别外挂名单

**中文库有自带的「收录 / 级别」筛选**（北大核心、CSSCI…）。**用它。**
与记录**同源**、覆盖**该库全部学科**、**无许可证问题**、**不过期**。

> 🔴 **外挂方案的实测证伪**：曾推荐某第三方中文期刊分级表，
> 下载后发现 **340 种里医学 0 种**；拿当轮 31 条记录的 22 种期刊去比 —— **命中 0 / 22**。
>
> → **教训**：**推荐工具前必须验证覆盖范围，不能只读 README。**
> 「某项目里有这个文件」≠「这个文件覆盖我们要的学科」。

### 环境

需本机重建 venv + 装 `DrissionPage` + 一份存过知网 cookie 的浏览器 profile。
**冷 profile 必 403。** 浏览器**必须是有头**。
