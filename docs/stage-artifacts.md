# 阶段中间格式

> **用途**：外部工具可以换，中间格式不换。换工具时只要求它产出被转换成下表规定的一种格式。
> 这张表是本仓与外部工具之间的稳定接口；表外的部分都属于可替换的实现。

## 一、为什么需要中间格式

各外部工具的输出形态互不相同：`nature-writing` 出分节 Markdown，`paper-spine` 出十二阶段目录，`nature-paper2ppt` 出 pptx，`nature-reader` 出 49 个块的 source_map。

检查器只能认一种格式。若不为每个阶段固定一种，换工具就必须重写解析与判据——那不叫换零件，叫换接口。

**中间格式优先复用本仓检查器已经认的格式**，不新造 schema。

## 二、格式清单

| 阶段 | 中间格式 | 认它的检查器 | 状态 |
|---|---|---|---|
| 检索 `retrieval` | `hits.jsonl`（一行一条：source, id, doi, title, year）+ `coverage.md` | 覆盖声明脚本（**尚未实现**） | 未接管 |
| 精读 `reading` | `note.md`：五态标签 + 定位方式 | `check_note` | 可用 |
| 写作 `drafting` | `draft.md`：分节标题 + `[n]` 引用标记 | `check_language`、`check_phrases`、`check_ref_citations` | 可用 |
| 润色 `polishing` | `draft.md` + 改写前快照 `draft.raw.md` | 同写作，另加 token 比对 | 可用 |
| 配图 `figures` | `figure/` 目录 + `figure_spec.json` | 图规格校验（**尚未实现**） | 未接管 |
| 统计 `statistics` | `analysis_plan.md`：主分析 / 协变量 / 多重比较 / 效应量 / 样本量 五节 | 无（人工） | 未接管 |
| 标书 `proposal` | `outline.md`：章节树 | `check_grant_rules` | 部分 |
| 汇报 `slides` | `deck.md`：制作稿七项 | `check_talk` | 可用 |
| 审稿 `review` | `review.md`：编号直述体 | `check_review` | 可用 |

## 三、转换的三档做法

| 档 | 情形 | 做法 | 记账 |
|---|---|---|---|
| 1 | 结构可预测 | 写确定性解析器 | 无需记录 |
| 2 | 结构不稳但可读 | AI 转换；保留原文，转换后抽样核对 | 日志记 `converted: true`，原文另存 |
| 3 | 读不出来 | 不接管，该阶段转人工 | **必须**在日志与报告中写「本阶段未接管」 |

第三档不是失败，但不记账就是隐瞒。

## 四、什么是稳定的，什么是可换的

| 稳定（改需升版） | 可换（随时） |
|---|---|
| 本表的阶段名与格式 | 每行「当前实现」是哪个工具 |
| 日志字段名 | 参与检查的检查器与阈值 |
| 检查器的输入输出形态（文件进、四列出） | 具体规则 |

改稳定项的条件只有一个：现有字段装不下新需求。改时升版本、写迁移说明，旧日志保留不动。

## 五、机器查不到的部分

中间格式保证的是**可判定项**能被查。以下各项任何检查器都不评，**格式合规不代表内容合格**：

- 论证是否成立
- 结构与推进次序是否合理
- 图表是否说明了它要说明的事

这几项由阶段收尾的结构化问答收集，见 `contracts/review-form.json`。
