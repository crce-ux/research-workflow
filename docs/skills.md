# 配套 skill 索引

这套工作流里的**方法**已沉淀成 6 个可独立安装的 skill。

---

## 什么时候用哪个

```
手上有份稿子要交        → text-self-review（自查迭代）
稿子读起来像 AI 写的    → ai-writing-debug（表达层）
要查一批文献、建证据表  → literature-pipeline
要做汇报 PPT、讲稿没底   → academic-slides（全链路）
受邀审一篇稿            → peer-review
要把想法变成研究方案    → study-design
```

---

## 六个 skill

### [`text-self-review`](https://github.com/crce-ux/text-self-review)
**迭代式文本自查（RCAI 循环）**

- **核心命题**：单轮自查必然留盲区，**盲区的形状由当轮采用的维度决定**
- 所以迭代靠「换维度」，不是「再读一遍」
- 23 个维度分 5 组；收敛判据；独立视角的**隔离纪律**
- **跑过对照评测**，含两处对自身不利的发现

### [`ai-writing-debug`](https://github.com/crce-ux/ai-writing-debug)
**AI 写作痕迹诊断与修复**

- 四个互不重叠的轴：叙事姿态 / 表达层四层扫描 / 文体适配 / 代笔身份匹配
- **口语节拍 ≠ 口语化**——「三条原因。」要留，「卡在哪」要清
- 交付形态是**定位到句 + 成因 + 改写**，不只是打分

### [`literature-pipeline`](https://github.com/crce-ux/literature-pipeline)
**文献调研流程纪律**

- **覆盖声明** `N → M → K`——只报「已检查」不报「没检查什么」，等于假装覆盖完整
- **四条铁律**：相关度是门槛 / **裸被引必须归一** / 权威的错误更危险 / 外在不覆盖内在
- G0 四项质控；12 列证据表口径

### [`academic-slides`](https://github.com/crce-ux/academic-slides)
**汇报讲者侧把关**

- **待核清零**——`待核/⏳/TODO` 扫成 0，不允许「保留但标注待核」
- 讲稿规格：240 字/分钟、每页 200–500 字、六样必带
- **理解确认四测试 + 磕巴判据**

### [`peer-review`](https://github.com/crce-ux/peer-review)
**同行评议完整流程**

- 接不接的 4 问 → 三遍阅读法 → 意见写法 → 给编辑的保密意见
- ⭐ **领域核查五层生成轴**（定义 / 前提 / 测量 / 分析 / 报告）+ 报告规范速查 + 三份样例
- COPE 伦理；诚信红线只写进保密意见

### [`study-design`](https://github.com/crce-ux/study-design)
**课题设计 D1–D5**

- **没有证伪条件，就不是科学假设**
- **效应量不可照搬文献**——患者组间比较必然更小
- 裁决四档；**说「不行」要有出处，感觉不算**

## 与现成 skill 的关系

这些 skill **不重复**已有的通用工具，它们补的是：

| 补什么 | 例子 |
|---|---|
| **覆盖纪律** | 报出「没查到什么」 |
| **归一化读法** | 裸被引会筛掉最好的新文 |
| **讲者侧** | 讲的人有没有内化——不是 PPT 本身 |
| **领域专属** | TRS 依从性、EEG trial 数平衡、ML 特征泄漏 |
| **自证性评测** | 跑对照评测并记录自己的不足 |
