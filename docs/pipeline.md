# 全流程 · P → A → B → C → D → E

```
P  日常精读      持续输入，不服务某个具体项目
A  文献侧        检索 → G0 → 证据表 → G1
B  内容侧        内容稿 → B2自检 → G2 → B3.5理解确认 → G3 → 制作稿
C  交付侧        生成 → 视觉验证 → G4 → 复核 → 快照
D  课题设计      D1子假设 → D2样本量 → D3入排 → D4可行性 → D5伦理
E  执行产出      数据 → SAP → 结果 → 论文 → 投稿 → 归档
```

---

## P · 日常精读

**定位**：持续输入。**不服务于某个具体项目**——它是 A 段的原料池。

| 环节 | 判据 |
|---|---|
| 选文 | 分级（A 精读 / B 泛读 / C 扫读找引文） |
| 笔记结构 | 固定字段，便于日后检索 |
| 回填 | 精读笔记 → 跨项目文献表 |

**产出**：`文献精读/` 下的笔记 + 文献表。

---

## A · 文献侧

### A1 · 检索

- **多源并行**：PubMed 拆成 2–3 个简查询（复杂查询易超时）；Google 中英文补充
- **三级筛选**：A 类（直接匹配）精读 / B 类（有差异）泛读 / C 类（综述指南）扫读
- **目标篇数**：每模块 15–25 篇精读核心

### G0 · 检索层质控（**四项硬性**）

| # | 项 | 不过会怎样 |
|---|---|---|
| 1 | **去重** | 同一篇占两个坑、篇数虚高 |
| 2 | **存在性**（回源反查） | **引了一篇根本不存在的文献** |
| 3 | **元数据完整**（缺的显式标注，不留空） | 填表时才发现缺，返工 |
| 4 | **版本**（预印本 / 正式版，同一研究只留一版） | 同一研究算两篇 |

> ⚠️ **第 2 项对 AI 协作尤其要紧**：AI 给出的 PMID/DOI **可能编造**。
> 一律回源核，包括那些「看起来很眼熟」的。

### A2 · 证据表

**单一数据源。** 讲解、综述、PPT 全部与之对齐——**一篇不差、一个数字不改**。

12 列 = 10 列 PICO + 2 列期刊指标。后两列的口径就是一切：
IF 标年份（`4.4 (2024 JCR)`）、分区标版本（`中科院医学2区(升级版2025) / JCR Q2`）。

> ⚠️ **不写口径等于没写。**

### G1 · 入库

**PMID ↔ DOI 一一匹配。**
手填的 PMID 一律按 DOI 反查。

## B · 内容侧

### B2 · 自检

三个脚本 + 两份清单：

| 查什么 | 工具 |
|---|---|
| 引用自足 / 排他性断言 / 数字口径 | `check_language.py` |
| 身份匹配（保守 / 越级 / 引据悬空 / 回指） | `check_persona.py` |
| 内容能否被接住 | 内容自检清单（八条标准） |

### G2 · 内容门禁（**硬门禁**）

**排他性断言 = 0**；缩写首次全展开。

### B3.5 · 理解确认

**「写完了」不等于「懂了」。**

四测试：术语表 / 数字表 / 追问清单 / 逐页一句话。
加一条最快的：**磕巴判据**——念一遍，磕巴处就是没内化的地方。

### G3 · 理解门禁

**逐页一句话说得出。** 说不出来就别做 PPT。

---

## C · 交付侧

### C1 · 生成 → C2 · 视觉验证

**双轨**：

- **客观轨**：像素体检（边缘泄漏 / 留白 / 边距 / 包围盒越界）
- **语义轨**：读图判断（无溢出 / 错位 / 口径错误）

> **客观轨定有无异常，语义轨定是不是问题。**

### G4 · 交付门禁

### C3 · 隐藏元数据 ⚠️

**逐页看内容查不出来的一类泄露。**

三个场景必查：

1. **做审稿人**（稿件含可识别信息需回避）
2. **自己投稿盲审**
3. **组会/外报 PPT 含未发表数据**

---

## D · 课题设计

```
D1 子假设落地 → D2 样本量 → D3 入排与分组 → D4 可行性 → D5 伦理与数据管理
        └────── 每步都能追到证据表（追不到 = 悬空依据）──────┘
```

四条铁律与 11 条坑，见 [`study-design`](https://github.com/crce-ux/study-design)。

## E · 执行产出

| 段 | 做什么 | 关键纪律 |
|---|---|---|
| **E1** 数据 | 变量字典（含**缺失码四类**） | 采集前建好 |
| **E2** 缺失 | 先报缺失率，再分类型，再处理 | **不得事后挑选处理方法** |
| **E3** SAP 执行 | **偏离记录** | **偏离本身不致命，不记录才致命** |
| **E4** 结果报告 | 效应量 + 95%CI（不只 p） | — |
| **E5** 论文 | 串联写作 skill | 保真红线：不改数字 / 单位 / 分母 / 方向词 |
| **E6** 投稿 | 选刊 + 盲审自查 | 看 `check_metadata_leak.py --scene blind` |
| **E7** 归档 | 成果台账 | 成果记录的唯一出处 |

---

## 三条贯穿的原则

1. **门禁不是建议。** 硬门禁（G0/G1/G2/G3）必须过，且**不分档**。
2. **命中 ≠ 要改。** 脚本报"可能"不代表要删——判据的最后一关永远是人。
3. **覆盖要说出来。** `N → M → K`，K 逐条列原因。
