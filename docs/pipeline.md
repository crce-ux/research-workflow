# 全流程与门禁 · P → A → B → C → D → E

> 本文合并了原先的 `gates.md`。

```
P  日常精读      持续输入，不服务某个具体项目
A  文献侧        检索 → G0 → 证据表 → G1
B  内容侧        内容稿 → B2自检 → G2 → B3.5理解确认 → G3 → 制作稿
C  交付侧        生成 → 视觉验证 → G4 → 复核 → 快照
D  课题设计      D1子假设 → D2样本量 → D3入排 → D4可行性 → D5伦理 → D6混杂复核
E  执行产出      数据 → SAP → 结果 → 论文 → 投稿 → 归档
```

> 📌 **每一步用哪个 skill——自研的与已装的都在——见 [`skills.md`](skills.md)。**
> 📌 **外部同类项目与它们的许可** → [`external-skills.md`](external-skills.md)。
> 📌 **工具怎么接** → [`runtime.md`](runtime.md)。

## 〇、五道门禁一览

| 门 | 卡在哪 | 判据 | 性质 |
|---|---|---|---|
| **G0** 检索层 | A1 → A2 之间 | 去重 / 存在性 / 元数据完整 / 版本——**四项全过** | 硬 |
| **G1** 入库 | A2 → 使用 | PMID ↔ DOI **一一匹配** | 硬 |
| **G2** 内容 | B2 之后 | **排他性断言 = 0**；缩写首次全展开 | 硬 |
| **G3** 理解 | B3.5 之后 | **逐页一句话说得出** | 硬 |
| **G4** 交付 | C2 之后 | 边缘 / 边距 / 四角**全 0** | 硬 |

**硬门禁必须过，不分档。**

### 唯一的回改回路

```
G4 发现问题  →  回 B4 改「制作稿」  →  重新生成
             ✗  不是直接改成品
```

**直接改成品的修正，下次重新生成会被覆盖。**

## 一、P · 日常精读

**定位**：持续输入。**不服务于某个具体项目**——它是 A 段的输入来源。

| 环节 | 判据 |
|---|---|
| 选文 | 分级（A 精读 / B 泛读 / C 扫读找引文） |
| 笔记结构 | 固定字段，便于日后检索 |
| 回填 | 精读笔记 → 跨项目文献表 |

**产出**：`文献精读/` 下的笔记 + 文献表。

---

## 二、A · 文献侧

### A1 · 检索

- **多源并行**：PubMed 拆成 2–3 个简查询（复杂查询易超时）；Google 中英文补充
- **三级筛选**：A 类（直接匹配）精读 / B 类（有差异）泛读 / C 类（综述指南）扫读
- **目标篇数**：每模块 15–25 篇精读核心
- **去重**：多源合起来先跑 `scripts/literature/dedupe_refs.py`——**去重做不干净会一路带到覆盖声明**

### G0 · 检索层质控（**四项硬性**）

| # | 项 | 不过会怎样 |
|---|---|---|
| 1 | **去重** | 同一篇占两个坑、篇数虚高 |
| 2 | **存在性**（回源反查） | **引了一篇根本不存在的文献** |
| 3 | **元数据完整**（缺的显式标注，不留空） | 填表时才发现缺，返工 |
| 4 | **版本**（预印本 / 正式版，同一研究只留一版） | 同一研究算两篇 |

> ⚠️ **第 2 项对 AI 协作尤其要紧**：AI 给出的 PMID/DOI **可能编造**。
> 一律回源核，包括看起来眼熟的条目。

### A2 · 证据表

**单一数据源。** 讲解、综述、PPT 全部与之对齐。

12 列 = 10 列 PICO + 2 列期刊指标。后两列必须带口径：
IF 标年份（`4.4 (2024 JCR)`）、分区标版本（`中科院医学2区(升级版2025) / JCR Q2`）。

> ⚠️ **不写口径等于没写。**

### G1 · 入库

**PMID ↔ DOI 一一匹配。** 手填的 PMID 一律按 DOI 反查。

## 三、B · 内容侧

### B2 · 自检

| 查什么 | 工具 |
|---|---|
| 引用自足 / 排他性断言 / 数字口径 | `check_language.py` |
| 身份匹配（保守 / 越级 / 引据悬空 / 回指） | `check_persona.py` |
| 内容能否被接住 | 内容自检清单（八条标准） |

### G2 · 内容门禁（**硬门禁**）

**排他性断言 = 0**；缩写首次全展开。

### B3.5 · 理解确认

四测试：术语表 / 数字表 / 追问清单 / 逐页一句话。
加一条最快的：**磕巴判据**——念一遍，磕巴处就是没内化的地方。

### G3 · 理解门禁

**逐页一句话说得出。** 说不出来就别做 PPT。

## 四、C · 交付侧

### C1 · 生成 → C2 · 视觉验证

**双轨**：

- **客观轨**：像素体检（边缘泄漏 / 留白 / 边距 / 包围盒越界）
- **语义轨**：读图判断（无溢出 / 错位 / 口径错误）

> **客观轨定有无异常，语义轨定是不是问题。**

**体检是一次，回路要跑到干净**：渲染 → 看图 → 改源 → 重渲染 → 再看。

### G4 · 交付门禁

边缘 / 边距 / 四角全 0。

### C3 · 隐藏元数据 ⚠️

**逐页看内容查不出来的一类泄露。** 三个场景必查：

1. **做审稿人**（稿件含可识别信息需回避）
2. **自己投稿盲审**
3. **组会/外报 PPT 含未发表数据**

## 六、E · 执行产出

| 段 | 做什么 | 关键纪律 |
|---|---|---|
| **E1** 数据 | 变量字典（含**缺失码四类**） | 采集前建好 |
| **E2** 缺失 | 先报缺失率，再分类型，再处理 | **不得事后挑选处理方法**；「不适用」不是缺失 |
| **E3** SAP 执行 | **偏离记录**（**七列**，含「何时决定」） | **偏离要记录，偏离本身不算错误** |
| **E4** 结果报告 | 效应量 + 95%CI（不只 p） | 分母（ITT / PP）要写 |
| **E5** 论文 / 综述 | 串联写作 skill | 保真界限：不改数字 / 单位 / 分母 / 方向词 / **否定** |
| **E6** 投稿 | 选刊 → **按刊重排** → 盲审自查 | 看 `check_metadata_leak.py --scene blind` |
| **E7** 归档 | 成果台账 | 成果记录的唯一出处 |

## 七、六条轴

**混着查会互相误报。** 同一个词，讲稿里是对的，幻灯片里就是错的。

| # | 轴 | 在哪查 | 查什么 |
|---|---|---|---|
| ① | **措辞的文体适配** | 写作禁用词清单 | 口语节拍 vs 口语化 |
| ② | **说法准不准** | 内容自检清单八条 | 自足 / 可答 / 有出处 / 不越原文 / 不哄 / 不设问 / 科学表述 / 维度齐 |
| ③ | **像不像他写的** | 身份匹配约束 | 术语层 / 引据层 / 立场层 |
| ④ | **像不像人写的** | 去味清单 | AI 味、套话 |
| ⑤ | **引用与断言** | `check_language.py` | 自足 · 排他性 · 量词 · 缩写 · 数字口径 |
| ⑥ | **身份匹配机检** | `check_persona.py` | 保守 / 越级 / 引据 / 回指 / 书面语 / 长句 |

### ② 与 ③ 最容易混

**② 问「这个说法站不站得住」，③ 问「这个身份的人写得出这句吗」。**
一句话可以站得住，但不像他写的——此时该改的是 ③，不是 ②。

## 八、门禁的落点：必须作出处置

机检产出的是**发现**，需人工判断。跑完当场三选一，并落笔：

| 出口 | 什么时候选 | 要写什么 |
|---|---|---|
| **改** | 文本确实没过自己写的线 | 改了什么 |
| **不改** | 判据对，但被命中的内容是故意保留的 | **为什么**——不写理由的「不改」等于没处置 |
| **改规则** | 判据本身不成立（误报） | 撤回 / 收窄了哪条，为什么 |

**落点**：项目的待修清单（科研库：`_系统/待修清单.md`）。规矩也写进了 `text-self-review`。

> 🔴 **跑工具 ≠ 改稿。** 拿真稿跑检查器是**验收工具**（看它报得准不准），不是改稿。
> 两者会切换，所以要有待修清单：**把工具的产出保留到下一个任务开始。**

---

## 九、三条贯穿的原则

1. **硬门禁（G0/G1/G2/G3/G4）必须过，且不分档。**
2. **命中 ≠ 要改。** 脚本报「可能」不代表要删，最终由人判断。
3. **覆盖要说出来。** `N → M → K`，K 逐条列原因。
